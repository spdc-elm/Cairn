V3.4 Stream Reliability

结论先行：此回归不是 SSH 或 Pi 的孤立问题，而是可靠事件链、终态屏障、UI 分页投影共同失效。

核心判断

临时补丁若只调 timeout，会掩盖真实问题。当前系统需要的是一条不会静默丢 tail、final、session、terminal status 的事件提交链。

P0

事件尾部可丢

EventSink.close() 可在 drain 失败后继续 patch terminal status。UI 看到 execution terminal 后停止追事件，final assistant 可能永久缺失。

P0

Conversation 只读头页

长 execution 前 200 条多为 partial/raw 时，final assistant/status 在后页，UI 初载拿不到，terminal 后也不再继续取。

P1

写侧背压扩散

/events、claim、healthcheck、heartbeat 共用 server/SQLite 写路径。一次写锁或慢事务会让 dispatcher 多类请求同时超时。

P1

语义来源不唯一

dispatcher projector 已产出标准 events，UI 仍解析 raw stdout JSONL。双投影会放大 partial/final 覆盖与重复问题。

失效链路

用户日志中的 read timeout 是链路中段的可见烟雾；它能解释半截输出，也能和 UI 截断独立叠加。

1. Worker 输出
Pi/Claude/Codex 通过 SSH 或 Docker 产生 stdout/stderr；SSH 当前以 readline() 为实时边界。
2. EventSink
raw stream 与 projector events 进入内存队列；flush timeout 后 batch 回队头，但无上限、无 spool、无 terminal barrier。
3. Server 写入
append events 每条分配 cursor 并写 SQLite。写锁、慢事务、healthcheck/claim 并发会让 dispatcher 10 秒 read timeout。
4. Terminal Patch
若 terminal patch 成功而 final events 失败，系统进入“execution 已结束、事件尾部缺失”的不一致状态。
5. UI 投影
Conversation 固定头页与有限轮询会把不一致固化为用户可见的“收到半截、后面没了”。

问题优先级

按“会不会静默丢用户答案”和“是否破坏 SSOT”排序。

级别问题必须约束
P0 terminal status 早于 final events 持久化 新增或等价实现 finish_execution(events, patch) 原子语义；无 final 屏障不得 succeeded。
P0 Conversation 长输出截断 初载 exhaust cursor、tail query，或 server projection；poll 至 terminal 且 final 可见。
P1 event_key 幂等过弱 同 key 同 canonical event 才幂等；不同 payload/type/role/ts 返回 409。
P1 cursor scope 过宽 execution cursor 属于同 execution，branch cursor 属于同 branch，跨 scope 400。
P1 branch/session 语义隐晦 branch_continue 明确定义为继续 branch 最新 successful session，不恢复 source。

目标设计边界

保留 v3.2 的核心心智模型，只加可靠性边界。旧路径不复活。

Dispatcher

有界背压

  • queue 上限与 retry 策略
  • close 最大等待
  • flush failed diagnostic
  • heartbeat 与 event flush 解耦预算
Server

强幂等与原子终态

  • immutable event_key
  • cursor scope 校验
  • SQLite busy timeout / retry
  • terminal events + patch 原子提交
UI

完整投影

  • 不只读头页
  • 不固定 180 秒静默停止
  • final 覆盖 partial
  • raw JSONL 不做主语义源
Proposed Architecture Delta：给 ExecutionEvent 主链路增加可靠性边界，而非改变 Fact/Intent/Execution/Branch 的基本分层。

验收口径

只以测试和真实流程说话。代码阅读不能自证 stream 可靠。

API / Server

  • 同 key 同事件重试不重复。
  • 同 key 不同 payload 返回 409。
  • 跨 execution/branch cursor 返回 400。
  • terminal finish 原子成功或整体失败。

Dispatcher

  • /events timeout 后可重试且不丢 tail。
  • 连续失败时 queue 不无限增长。
  • final assistant append 不静默失败。
  • 慢 flush 不误杀 worker heartbeat。

UI

  • 250+ events 后仍显示 final。
  • 超过 180 秒仍可恢复追踪。
  • partial/final 不重复、不半截。
  • 刷新后 timeline 完整恢复。

SSH / Pi E2E

  • Pi fork 长回复完整显示。
  • 第二轮继续 fork branch session。
  • session id、message、terminal status 全可追溯。
  • cancel/timeout 后远端残留有诊断。
