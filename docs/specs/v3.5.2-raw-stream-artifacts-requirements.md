# V3.5.2 Raw Stream Artifacts Requirements

日期：2026-05-22
状态：需求草案
依据：用户反馈少量 project 后 `cairn.local.db` 膨胀至约 1.3GB，并指出 `execution_events` raw stdout 中 Pi `agent_end.messages` 重复携带完整会话历史；用户要求从第一性原理重设存储边界、压低存储开销、与 v3.5 agent context 共用一次 E2E。已读取 `docs/architecture/cairn-architecture-ssot.md`、`docs/specs/v3.4-stream-reliability-requirements.md`、`docs/specs/v3.5-agent-context-requirements.md`、`cairn/tests/e2e_test.md`、`cairn/src/cairn/dispatcher/runtime/event_sink.py`、`cairn/src/cairn/dispatcher/runtime/run_logs.py`、`cairn/src/cairn/dispatcher/workers/adapters/pi.py`、`cairn/src/cairn/shared/worker_events.py`、`cairn/src/cairn/server/services.py`、`cairn/tests/e2e/test_v34_stream_reliability_smoke.py`。

## 1. 核心判断

DB 是 ledger，不是 transcript warehouse。

从第一性原理看，Cairn 对 worker 输出有五类需求：

- Conversation/Output 主视图要可实时显示、分页追溯、fork/resume 可用。
- Session、tool、assistant final、terminal status 必须可靠入账。
- Debug 时能找到完整 worker raw stream。
- 旧数据能清理回收空间。
- 少量 project 不应让 SQLite 主 DB 膨胀到 GB 级。

因此目标边界应是：

- `execution_events` 保存语义事件：`message`、`tool`、`session`、`status`、`artifact`、少量 `metric/diagnostic`。
- 完整 raw stdout/stderr/worker JSONL 保存为 run log/artifact 文件，不进入主 DB。
- DB 中 raw 只保留 bounded preview 或 raw artifact ref，用于 Raw/Debug 页快速定位。
- Pi `agent_end.messages` 这类重复完整历史绝不完整写入 `execution_events.payload_json`。

这比“把 raw stdout 截断后仍大量写 DB”更干净：完整 raw 的天然形态是 append-only 文件，语义事实的天然形态才是 DB 事件。

## 2. 背景与现状

当前事实：

- `ExecutionEventSink.write_stream()` 会将每段 stdout/stderr 原样写成 `stdout`/`stderr` event，再调用 projector 投影 message/tool/session。
- `RunLogWriter.write_stream()` 已把完整 redacted stream 写入 run log JSONL。
- Pi projector 需要读取 stdout JSONL，并可从 `agent_end.messages` 中提取 final assistant fallback。
- Pi projector 当前还会把 `agent_end.messages` list 放入 `_pending_agent_messages`，直到 close 时再反向查找最后 assistant；这虽然不直接入 DB，却会在 dispatcher 内存里重复持有完整会话历史。
- v3.4 已建立 finish contract、cursor scope、长流式输出完整同步等可靠性要求。
- UI Raw/Debug 当前可读取 `stdout`/`stderr` events，但 Conversation 主视图不应依赖 raw stdout parser。

问题：

- Pi `agent_end.messages` 包含完整历史；每轮 execution 重复写入 DB raw stdout。
- DB 同时保存 raw stream 与 semantic projection，造成重复存储。
- SQLite 主 DB 需要承担查询与交互，不适合无限日志归档。

## 3. 目标

- 完整 raw stream 不再进入 `execution_events` 主 DB。
- 保留 v3.4 功能等价：长流式 assistant final 可见、terminal status 可见、fork/resume/session 不回归。
- Debug 仍可从 run log/artifact 找到完整 redacted raw stream。
- UI Raw view 显示 bounded preview、omitted bytes、artifact/log 指针。
- Pi adapter 不在内存中长期保留完整 `agent_end.messages`；只保留 final assistant fallback 所需的 bounded text/metadata。
- 提供旧 DB 显式清理命令，把已有大 raw payload 裁剪为 preview/ref，并可 `VACUUM`。
- 旧 DB 清理必须保留既有 project/execution/semantic events，例如用户当前想保留的 `proj_004`；只裁剪 raw stdout/stderr payload，不把长期旧库兼容写进主线架构。
- 与 v3.5 agent context 共用一次 E2E 验收，并检查 DB raw payload 增长受控。

## 4. 非目标

- 不删除 `ExecutionEvent` 主链路。
- 不把完整 raw stream 移入新的 DB 表。
- 不恢复 `/runs/*/transcript`、`run_provenance`、`/questions` 或 server backend transcript parser。
- 不保证 DB Raw view 可还原完整 stdout；完整 raw 属于文件/artifact。
- 不在普通 migration 中自动清理既有 DB；清理必须由显式 maintenance 命令触发。

## 5. 用户流程

1. Worker 运行，产生 stdout/stderr。
2. Dispatcher 将完整 redacted stream 写入 run log/artifact 文件。
3. Dispatcher 将完整 stream 交给 projector，生成 semantic events。
4. Dispatcher 将 semantic events 写入 `execution_events`。
5. Dispatcher 只向 DB 写 raw preview/ref/metric，不写完整 raw JSONL。
6. UI Conversation 从 semantic events 显示完整对话。
7. UI Raw/Debug 显示 preview、omitted bytes、artifact/log path 或下载入口。
8. 用户需要瘦身旧 DB 时，运行显式 prune 命令，再选择是否 `VACUUM`。

## 6. 功能需求

- EventSink 必须分离两条路径：
  - projector path：接收完整 redacted stream，用于生成 semantic events。
  - DB raw path：只生成 bounded preview/ref/metric。
- Run log/artifact 必须保存完整 redacted raw stream：
  - 至少记录 path、size、content hash、project_id、execution_id、stream kind。
  - 若 artifact 表易接入，登记 `Artifact(type="transcript" 或 "file")`；否则 execution metadata 必须记录 run log path/hash/size。
- Raw ref 必须可解析：
  - 首选 `artifacts` 表记录 artifact id/path/hash/size。
  - 若首版不接 artifact，`execution_runs.metadata_json.raw_stream` 必须记录等价 ref。
  - `stdout`/`stderr` preview payload 中的 `raw_ref` 必须能指向上述 artifact 或 metadata ref，而不是只写不可追踪的本地字符串。
- DB raw preview 必须有硬上限：
  - 每 execution 每 stream preview 总量建议不超过 16 KiB。
  - 单条 preview event 建议不超过 4 KiB。
  - 超出后只记录 omitted bytes/metric，不再写 raw text。
- `stdout`/`stderr` event 可保留，但语义变为 raw preview，不再承诺完整 stream。
- Pi JSONL sanitiser 必须作用于 DB raw preview：
  - `agent_end.messages` 替换为 `messages_omitted: true`、`messages_count`、`messages_omitted_bytes`。
  - projector 仍使用完整 stream，保证 final assistant fallback。
- Pi projector 自身必须避免内存型重复：
  - 不再保存完整 `_pending_agent_messages`。
  - 解析 `agent_end.messages` 时只提取最后 assistant fallback text、messages_count、omitted bytes 或 equivalent summary。
  - fallback text 可按 assistant message 语义预算保留完整最终回答；不得保留历史 user/tool/message 数组。
- Semantic events 不得因 raw preview 策略被截断：
  - assistant final 不截断。
  - tool/session/status 不丢失。
  - terminal status 仍通过 finish contract。
- 若某 worker 无 semantic projector，则 DB 仍只保存 bounded raw preview；完整 raw 在 artifact 文件中。
- 旧 DB cleanup 命令：
  - dry-run 默认，只统计。
  - apply 必须 `--yes`。
  - 可选 `--vacuum` 回收 SQLite 文件体积。
  - 保留 event id、cursor、seq、event_key，避免破坏已有 UI cursor 与审计顺序。
  - 保留 project、execution、message/tool/session/status semantic events；不得为了压缩 DB 删除 `proj_004` 这类仍有价值的 project 历史。
  - 该命令是一次性 maintenance path，不要求未来 schema/代码为旧 raw blob 做长期兼容分支。

## 7. 数据/API/界面需求

### 数据

- 不新增核心 runtime 表。
- 可复用 `artifacts` 表登记 raw stream 文件；若实现阶段发现 artifact 语义不合，可先在 `execution_runs.metadata_json` 记录 raw stream ref，并把 artifact 化作为后续增强。
- `stdout`/`stderr` event payload 新增字段：
  - `text`: preview。
  - `preview: true`
  - `truncated: true|false`
  - `omitted_bytes`
  - `raw_ref`: path/artifact id/run_log id。
  - `sanitised: true|false`
- `metric` event 可记录 raw storage stats：
  - `raw_bytes_seen`
  - `raw_bytes_persisted_to_db`
  - `raw_bytes_written_to_file`
  - `raw_events_omitted`

### API

- Execution events API 保持现有路径。
- Raw preview events 向后兼容仍有 `payload.text`。
- Execution detail API 或 artifact/debug API 必须暴露 raw stream ref，使 UI/运维能从 execution 定位完整 run log/artifact。
- 不新增完整 raw Conversation 主链路 API；若需要下载完整 raw，应走 artifact/debug endpoint，不进入 Conversation API。

### UI

- Conversation 主视图只消费 semantic events。
- Raw/Debug view：
  - 显示 preview。
  - 显示 omitted bytes 与 raw ref。
  - 不把 preview truncation 当作 worker failure。
- Export 默认不展开完整 raw stream，只导出 ref/metadata；完整 raw export 需显式 debug/attachment 语义。

## 8. 关键决策点

- 是否立即 artifact 化 raw stream：建议优先 artifact 化；如果改动过大，至少 execution metadata 记录 run log ref。
- 默认 DB preview budget：建议 stdout/stderr 各 16 KiB，比上一版 64 KiB 更符合“DB 非日志仓库”的边界。
- 清理命令是否处理所有 project：默认全库 dry-run；apply 支持 `--project-id` 与 `--execution-id`。
- Run log retention 不在本需求内；本需求只把主 DB 热路径降下来。

## 9. Proposed Architecture Delta

当前 SSOT 事实：

- `ExecutionEvent` 是实时 Output、conversation transcript、tool/message stream、stdout/stderr 的唯一主数据源。
- Raw stdout/stderr 目前可作为 execution events 进入主 DB。

目标事实：

- `ExecutionEvent` 仍是实时 Output/Conversation 主数据源，但完整 raw stdout/stderr 不属于主 DB 职责。
- `ExecutionEvent` 中的 stdout/stderr 只表示 bounded preview/ref/diagnostic，不承诺完整 raw stream。
- 完整 raw stream 属于 run log/artifact 文件层；DB 保存 semantic events 与 raw artifact/ref metadata。
- Dispatcher 负责将同一 worker stream 分发到 file sink、semantic projector、DB preview/ref sink。
- 旧 raw event 清理由显式 maintenance command 完成。

受影响 SSOT 章节：

- `3. 运行层主链路`
- `5. Dispatcher / Server / Driver 边界`
- `7. UI 投影规则`
- `8. 迁移与兼容策略`

行为不变项：

- Output/Conversation 主视图仍从 `ExecutionEvent` semantic events 投影。
- fork/resume/session、finish contract、cursor scope 不变。
- 不恢复旧 `/runs`、`/questions`、`run_provenance`。

Delta 成为 current 的条件：

- EventSink 三路分发实现完成：file sink、projector、DB preview/ref。
- Pi `agent_end.messages` 不再完整进入 DB。
- Cleanup command 实现完成。
- Unit/API/UI/E2E 验证功能等价和 DB raw payload 降低。
- SSOT 主体合并新事实并移除 Pending marker。

## 10. 验收标准

- 完整 Pi raw JSONL 不进入 `execution_events.payload_json`。
- `agent_end.messages` 不完整进入 DB。
- Dispatcher 运行时不长期保留完整 `agent_end.messages`；Pi projector 对该事件只保留 fallback summary/text。
- 长流式 E2E 中 assistant semantic message 包含首尾标记，terminal status 可见。
- 同一 E2E 中 `stdout`/`stderr` payload 总量低于预算，例如单 execution < 48 KiB。
- 对足够大的 raw stream，DB persisted raw bytes / original raw bytes < 0.25，并同时满足绝对预算；不能只靠相对比例掩盖小样本。
- Run log/artifact 文件存在，记录完整 redacted raw stream ref、size、hash。
- Execution API 能返回可解析 raw ref；raw ref 与 run log/artifact 文件 size/hash 一致。
- Raw/Debug UI 显示 preview、omitted bytes、raw ref。
- Conversation semantic message 中不出现 raw truncation marker、`messages_omitted`、preview/ref 调试字段。
- Resume/fork 等价性不回归：`resume_continue` 使用源 session 并进入 source/main Output；fork/branch continue 使用 branch session 且不污染 main history。
- Cursor pagination 等价性不回归：用小 limit 翻页仍能读到 semantic final assistant 与 terminal status。
- Cleanup command 可 dry-run、apply、vacuum，并保留 event order/cursor。
- Cleanup command 在真实或复制旧 DB 上验证：`proj_004` 仍可打开，semantic Output/Conversation 仍可读，DB 文件体积或 page count 明显下降。
- v3.4 stream reliability tests 不回归。
- 与 v3.5 agent context 共用一次 E2E，按 `cairn/tests/e2e_test.md` 完整验证后关闭所有测试监听服务。

## 11. 独立审查摘要

复杂度：architecture-or-runtime。

实际审查：2 个 fresh-context sub-agent，分别从存储边界与 E2E 等价性角度审查。

已采纳的关键发现：

- DB 应明确是 ledger，不是 transcript warehouse；完整 raw JSONL 必须落 run log/artifact，DB 只留 semantic events 与 bounded preview/ref/metric。
- `stdout`/`stderr` event 的新语义必须写入 SSOT：它们只是 bounded debug projection，不再承诺完整 raw。
- Pi projector 不能只解决“raw 入 DB”，还要避免在 `_pending_agent_messages` 中长期保留完整 `agent_end.messages`；spec 已补内存边界。
- Raw preview 的 `raw_ref` 必须可解析到 artifact 或 `execution_runs.metadata_json.raw_stream`，不能是不可追踪文本。
- 共享 E2E 不能只看 UI；必须同时验证 resume/fork、cursor 分页、semantic conversation 等价、agent context materialization 证据、DB 绝对/相对字节预算、Pi sanitise 负断言与 run log 完整证据。

未采纳或降级：

- 未强制首版必须 artifact 表落库。理由：如果 artifact 接入代价显著高于收益，`execution_runs.metadata_json.raw_stream` 可作为 MVP ref；但 ref 必须经 API 可见且可解析，不能只存在本地 run log。

## 12. 待确认问题

- Full raw artifact 是否需要首版提供浏览器下载入口；若不做，至少要能从 API metadata 找到本地路径。
- stdout/stderr preview 是否各 16 KiB 足够；若用户常用 Raw view 诊断，可提高到 32 KiB，但不应超过 64 KiB。
