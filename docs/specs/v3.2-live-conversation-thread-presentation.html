V3.2: Fact/Intent DAG + Execution Ledger

第一性原理重审后的结论：CAIRN 的用户心智模型仍是 origin 到 goal 的 Fact/Intent DAG；worker 的一次 execution 是运行时原子。最佳模型是让 fact/intent 承载问题图，让 execution/event/branch/artifact 承载调度、输出、session 与证据。

不选

保守修补

继续维护 question_threads/jobs/events 与 run_provenance。短期快，长期仍是多事实源。

推荐

Execution Ledger

ExecutionRun + ExecutionEvent 做唯一实时底座，Fact/Intent 仍是用户图层。

暂缓

Pure Execution Graph

理论最统一，但会把调度和知识黑板都变成 path query，首版过重。

推荐主干

Goal Project 目标、环境、策略的容器。
Work Intent 图上的探索边，也是工作订单：from facts、to fact、requested worker、timeout。
Run ExecutionRun 一次 worker 执行：身份、环境、session、lease/heartbeat/cancel、输入快照。
Stream ExecutionEvent append-only event stream；Output 与 Conversation 的唯一实时入口。
Session Branch fork/resume 的连续线；下一轮 session 从最近 run 推导。
Knowledge Fact / Artifact fact 是一次探索的结果节点；artifact 保存证据与大产物。
需求 落点 验收
Running Output UI 轮询 ExecutionEvent cursor，不再等 successful provenance。 刷新可追进度
Resume 本地可见 resume 是 branch 下新 execution；远端回复落成 message events。 远端与本地一致
Fork 多轮连续 同一 fork branch 连续追加 execution；session 由上一轮 remote_session_out 推导。 Pi / Claude 连续
Graph 简化 一次 concluded intent 产一个 result fact；证据由 execution/artifact/link 追溯。 可解释可追责
破坏兼容

DB 策略

V3.2 不为旧 question/runtime schema 保留长期兼容。建议备份当前 DB 后 destructive reset 到新 schema；旧实验数据只做一次性 best-effort import。
