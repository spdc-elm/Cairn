从自动 agent 到指挥部黑板

v2 的本质不是多一个筛选框，而是把决策权与执行权拆开：人类或可选 reason 决策，worker 只执行 intent，并留下可查证报告。

默认人工决策

新项目默认不启动 auto reason。人类可以手动创建、修改、撤回 intent。

执行者不决策

普通 worker 不生成新 intent，只写 report 与简短 fact。

黑板保简

Fact 是摘要节点；细节进入 workspace report，并由 metadata 连接。

审查重点：是否接受 `auto_reason = false` 作为默认行为，以及 bootstrap 是否也应受显式开关控制。

决策和执行的硬边界

Cairn v2 把“案件组黑板”作为协议真相源，把 worker 降级为可替换执行单元。

Commander读黑板，创建或修改 intent。
Server保存 project、intent、fact、metadata 与控制状态。
Dispatcher按 worker name、timeout、环境与容量调度。
Worker只执行 intent，写 report。
Blackboardfact 简述结果，metadata 指向报告。
角色能做不能做
Reason agent仅在 auto_reason 开启时生成 intent默认自动运行
Explore worker执行一个 intent，写 report，返回 fact自行派生下一步 intent
Human指定 worker、timeout、收尾、重跑或撤回无

用户选择 worker.name

UI 展示 `pi-GPT5.5` 这类具体兵种；`max_running` 决定同一兵种可同时出几路。

workers:
  - name: pi-GPT5.4
    type: pi
    task_types: [bootstrap, reason, explore]
    max_running: 2
    priority: 0
    model_profile: pi-GPT5.4
    endpoint: pi-default

  - name: pi-GPT5.5
    type: pi
    task_types: [bootstrap, reason, explore]
    max_running: 2
    priority: 0
    model_profile: pi-GPT5.5
    endpoint: pi-default
人工 intent可指定 `requested_worker = "pi-GPT5.5"`，不受 project 自动池限制。
自动 intentreason 生成的 intent 不指定 worker，由 dispatcher 在 project 自动池内选择。
兵力不足保持 pending，不 fallback。人类可撤回、修改、等待或重跑。

Timeout 进入控制面

人类可调 intent timeout；也可请求正在执行的 intent 进入收尾，而不是粗暴杀死任务。

优先级

intent.timeout_override

project.default_timeout

dispatcher task default

fallback 也失败

写失败 report。

intent 回到 pending。

由人决定重跑、修改或撤回。

`request_conclude_now` 的语义是进入收尾，不是判定失败；它应复用 timeout fallback / resume 机制。

v2 验收清单

首版要证明协议边界成立：默认人工、可指定 worker、报告可追溯、timeout 可控。

必须有

新项目默认 `auto_reason=false`；人工 intent 可指定 `requested_worker`；worker 繁忙则 pending；fact metadata 记录 report path。

可以后置

WebUI 远端 report 预览、terminal attach、完整 admin 并发治理、长期会话问答。

风险规避
report 未落盘却写成功 factdispatcher conclude 前硬检查。
人工指定 worker 被静默替换无可用兵力时 pending，不 fallback。
Docker/SSH 路径语义分裂统一 `CAIRN_WORKSPACE` 与 workspace 内路径。
