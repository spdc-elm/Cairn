Stream Reliability E2E

本页只看最终测试与验收。通过标准以用户可见效果为准：长回复不断、final 不丢、刷新可恢复、真实 Pi/SSH 通过。

总门槛

V3.4 只有三种结论：通过、阻塞、失败。mock E2E 只能证明本机机制；真实 Pi/SSH 未跑时，不得写 complete。

必须通过

长 stream 不截断

300+ events 后，Conversation 仍能显示 final assistant 与 terminal status；刷新后同样可见。

必须通过

长问题不静默停止

运行超过 180 秒时，UI 不得清空 active job，不得伪装完成；应继续追踪或显示可恢复状态。

硬门槛

真实 Pi/SSH sign-off

Pi worker fork 长回复必须完整；缺少真实环境时结论只能是 blocked，不是 passed。

用户可见效果验收断言失败信号
聊天记录不再“收到一半就没了” final assistant、session id、terminal status 均可从 execution events 追溯。 terminal succeeded 已显示，但 final assistant 缺失。
远程仍在工作时，前端不假死 超过 180 秒仍保持 running/recoverable 状态，并继续 cursor polling。 固定轮询上限后停止更新且无诊断。
刷新页面能恢复完整 timeline 重新打开项目/branch 后，完整 Conversation 与 Output 可恢复。 只显示头 200 条，尾部 final/status 丢失。
故障可见，不静默成功 append timeout、queue full、terminal barrier failed 等诊断进入日志或 execution events。 后台报 timeout，UI 显示成功且无错误细节。

浏览器验收

前端验收必须用浏览器或 JS DOM 证明最终效果，不能只靠 grep。核心是用户真的能看到完整对话。

B1 · 300+ events
mock worker 连续产生 300 条以上 message/tool/raw/status events，最后写 assistant final。
Conversation 中 final assistant 可见；terminal status 可见；无头页截断。
B2 · 超 180 秒
question execution 人为超过旧 UI 固定轮询上限。
界面仍显示 running 或 recoverable；继续追事件，不清掉 active job。
B3 · 刷新恢复
长 stream 完成后刷新页面，重新选择同一 execution/branch。
完整 Conversation、Output、terminal status 均恢复。
B4 · 切换隔离
运行中切换 selected execution/branch，再切回。
旧 timer 不得写入当前 selection；不会把别的 execution 的尾部覆盖进来。
B5 · Raw 分离
stdout 中放入 backend-specific JSONL。
Raw view 可见；Conversation 主视图不把 raw JSONL 二次解析成 assistant message。

后端与故障注入

后台验收目标是：timeout 可以发生，但不会造成重复、跳读、伪成功或无诊断。

测试域要注入的故障通过标准
Event idempotency 同一 event_key 重放；同 key 不同 payload/type/role/ts。 相同事件幂等返回旧 row；冲突返回 409，且不消耗 cursor。
Cursor scope 把其他 execution/branch 的 cursor 用到当前 endpoint。 返回 400；不得返回空页，也不得跳过当前 execution 早期事件。
Finish barrier terminal events 成功/失败、terminal patch 成功/失败、重复 finish。 terminal events 与 status 同事务；失败整体 rollback；重复同 payload 幂等，异 payload 409。
EventSink backpressure /events read timeout、连续失败、队列满、close 超时。 有 bounded wait、retry、fail-fast 或 diagnostic；不得静默丢 final。
Heartbeat isolation event append 慢 20 秒；claim/heartbeat 与 flush 同时拥塞。 heartbeat 不因 event flush 背压误杀 worker；延迟有可见 diagnostic。
Question final ordering final assistant append 失败或响应超时。 final 不绕过可靠链路；finish 前能证明 terminal events 已持久化。

真实 Pi/SSH

这是用户问题的最终复现路径。mock 通过而 Pi/SSH 未跑，只能说明局部机制可用；不能宣布 V3.4 完成。

场景 1

Pi fork 长回复

  • 从 source execution fork。
  • 生成超过 180 秒或超过 250 events 的长回复。
  • 最终 assistant 回复完整显示。
场景 2

branch_continue

  • 第二轮继续 fork branch。
  • worker 使用 fork branch 最新 session。
  • 不得误恢复 source branch session。
场景 3

cancel / timeout 残留

  • 触发 cancel 或 timeout。
  • 检查远端 process group / state path。
  • 残留必须有 system diagnostic。
Pi/SSH 验收项必须看到不能接受
长回复完整性 Pi worker 最终回复完整，尾部不丢。 只看 dispatcher 日志说还在跑，UI 没有 final。
事件可追溯 session id、assistant final、terminal status 都在 execution events。 final 只存在 raw stdout 或临时 transcript。
自动断言 gated pytest 对回复完整性、session 连续性、terminal 状态有断言。 人工看日志替代测试。
环境缺失 最终状态标记 blocked，列出缺失的 SSH/config/secret。 用 mock E2E 代替 sign-off。

通过判定

最终报告只应按此判定，不按“感觉好了”判定。

状态条件最终说法
Passed 合约测试、浏览器 E2E、mock E2E、真实 Pi/SSH、全量回归全部通过；SSOT 已合并实现事实。 V3.4 stream reliability 完成。
Blocked 自动测试通过，但真实 Pi/SSH 环境、secret、dispatch config 或远端 worker 不可用。 本地机制通过；真实 sign-off 阻塞，不宣布完成。
Failed 任一 P0 验收失败：final 丢失、长轮询静默停止、cursor 跳读、terminal 伪成功、Pi 长回复截断。 继续定位，不进入收尾。

最低可接受证据

  • 测试命令输出。
  • 浏览器 E2E 截图或 trace。
  • 真实 Pi/SSH gated test 结果。
  • 失败 diagnostic 的 execution event 示例。

不得作为证据

  • 只调大 timeout。
  • 只看 mock worker 成功。
  • 只看 dispatcher 日志没有报错。
  • 人工观察替代自动断言。
