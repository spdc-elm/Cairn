# V3.2.1 Claude Code Observability Execution Plan

依据：`docs/architecture/cairn-architecture-ssot.md`、`docs/specs/v3.2-live-conversation-thread-requirements.md`、`docs/plan/v3.2-live-conversation-thread-execution-plan.md`、`cairn/tests/e2e_test.md`
日期：2026-05-21
状态：implementation plan

## 1. 架构校准

v3.2 主链路不变：

```text
worker CLI stdout/stderr
-> dispatcher run_worker_process
-> ExecutionEventSink
-> server execution_events
-> Output UI / Conversation projection
```

当前实现已删除 server transcript/question 主路，`ExecutionRun`、`ExecutionEvent`、`Branch` 也已成主数据面。但仍有偏离：

- Claude Code stdout/stderr 已进入 Raw；结构化 Messages/Tools 主要靠前端从 raw stdout 解析，不是 dispatcher parser/projector 产出的统一 `ExecutionEvent`。
- parser 崩溃没有 system diagnostic event；Raw 虽保留，但用户看不到“解析层坏了，不是 worker 没输出”。
- `run_worker_process` 先写 terminal status event 再 patch terminal row，顺序正确；但 question task 手工 final message 与 sink close 之间仍需护栏，防止最后 assistant message 被 terminal status 抢先。
- Claude Code fork/resume driver 使用 stream-json，但 session lineage 需用 `ExecutionRun.remote_session_in/out` 与 `session_action` 护栏覆盖多轮。
- 后处理失败已有 `_mark_execution_postprocess_failed`，仍需测试确认不会留下 succeeded + active intent 的误导状态。

## 2. 改动范围

计划改：

- `cairn/src/cairn/dispatcher/runtime/event_sink.py`：Raw first，接入 worker stream projector，parser 失败写 system diagnostic。
- `cairn/src/cairn/dispatcher/workers/adapters/claudecode.py`、`pi.py`、`base.py`：提供 stdout JSONL -> message/tool/session/status 的规范化投影；driver 只处理 worker 差异。
- `cairn/src/cairn/dispatcher/tasks/{bootstrap,explore,reason,questions}.py`：构造 `ExecutionEventSink` 时传入 driver projector；question final assistant message 保持 terminal 前写入。
- `cairn/src/cairn/server/static/index.html`：Output 继续只读 execution/branch events；Messages 优先消费 message/tool events，同时 Raw 展示 stdout/stderr；stream partial 用 `stream_key` 压缩。
- 测试：补 dispatcher/server/UI guard，覆盖 Raw、parser diagnostic、Claude final message、terminal 顺序、session lineage、后处理失败。

明确不碰：

- 不恢复 `run_provenance`。
- 不恢复 `/runs/*/transcript`、`server/transcripts/*`、`/questions` 作为主路径。
- server 不 import dispatcher driver。
- dispatcher 不直写 DB。
- UI 不调用旧 transcript/question API。

## 3. RED/GREEN 顺序

1. RED：补 UI 旧路径禁用测试，确认 Output/Ask 不调用 `/runs/*/transcript`、`/questions`。
2. RED：补 dispatcher 测试，断言 Claude Code raw stdout/stderr 必达，parser 失败仍有 Raw + system diagnostic。
3. RED：补 Claude Code final assistant message 与 streaming partial compact key 测试。
4. RED：补 execution terminal status 顺序测试：final assistant message 早于 terminal status。
5. RED：补 fork/resume session lineage 多轮测试，含 Claude Code `fork_initial` -> `branch_continue`。
6. RED：补后处理失败测试，断言 execution row `failed/error_detail` 明确且 diagnostic event 可见。
7. GREEN：实现 projector、sink、UI 小改。
8. GREEN：跑 `env PYTHONPATH=cairn/src python -m pytest cairn/tests -q`。

## 4. E2E 路径

按 `cairn/tests/e2e_test.md`：

- 准备 `pentestVM` SSH 与专用 DB `cairn/tests/e2e/cairn.e2e.db`。
- 启动 server 与 dispatcher，使用非占用高端口。
- 浏览器验证 Pi：创建项目、执行探索、Output Raw/Messages/Tools 切换、fork 多轮、resume。
- 浏览器验证 Claude Code：同一路径，重点观察 stream-json partial 不堆叠、最后 assistant message 不丢、terminal status 不滞留 running。
- 人工制造/模拟 parser failure 与 postprocess failure，确认 Raw 和 diagnostic 可见，execution 状态明确 failed。
- 验收后关闭测试监听服务。
