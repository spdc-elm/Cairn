V3.2 Plan: 先立账，再迁移，最后清场

审查后的关键修正：不先 destructive reset。先 additive 建 ExecutionRun/Event，让旧流程双写并验证实时输出；迁移期间保持 UI/API 可用，再逐步切 dispatcher lease、Branch conversation、UI polling，最后删除旧 runtime。

拒绝

先 reset 再改 dispatcher

当前调度仍依赖 intent/project/question lease。先删旧表会让中间态不可运行。

采用

Additive Ledger + 双写

先把 execution/event 建起来，用 event sink 双写 DB 与 JSONL mirror，再逐 task 切换。

最后

Destructive Cleanup

等 server、dispatcher、UI smoke 通过后，再 reset 到 fresh v3.2 schema。

边界契约

Server

拥有 Fact/Intent DAG 与 execution ledger 持久化。所有 Fact/Intent/EvidenceLink mutation 都在 server 事务中完成。

Dispatcher

只执行 runtime：lease/patch execution、append events、upload artifacts、submit conclude request。不直接改语义图。

Shared parser

cairn.shared.worker_events 只放通用 DTO；backend normalizer 不进 server 主路径。

Health

worker_runtime_health 仍是 availability read model；healthcheck execution 只做审计。

阶段路线

0

RED 护栏

migration/reset、cursor concurrency、session locks、cross-plane imports、legacy runtime imports。

1

Additive Ledger

新增 execution_runs、execution_events、branches、artifacts、execution_session_locks，旧表暂保留。

2

Event Sink 双写

stdout/stderr/message/session 实时写 ExecutionEvent；JSONL 降级为 mirror artifact。

3

Dispatcher Lease 迁移

bootstrap/explore、reason、conclude、healthcheck、question 逐步切到 execution lease；Phase 内必须保留 facade 或 projection，不能让旧 UI 断裂。

4

Branch Conversation

Branch 替换 question thread；显式 session_action；resume 用 execution_session_locks 防并发污染。

5

UI Live Polling

Graph 提供 active/latest execution；Output 与 Conversation 使用 cursor 续读。

6

Cleanup / Reset

实现 backup/restore，普通 migrate 遇旧 schema fail-fast，最后删除 run_provenance 与 question_* 主路径。

关键修正
  • 创建 pending execution 与 dispatcher lease existing pending 分离。
  • execution ownership matrix 防止新版 run_provenance 垃圾桶。
  • 并发 intent 是 scheduler policy，不是本体约束。
  • session_action 入 schema，不藏 metadata。
  • conclusion report 由 server 单事务写 Fact/Intent/EvidenceLink。
验收重点
  • running output 刷新后不断流。
  • Pi / Claude fork 两轮连续。
  • Fork availability/reason 原样来自 server projection 与 inventory。
  • unhealthy source identity 禁 Fork/Resume，Fresh Context 可用。
  • fresh v3.2 schema 无旧 runtime 表和 intent live lease 字段。
