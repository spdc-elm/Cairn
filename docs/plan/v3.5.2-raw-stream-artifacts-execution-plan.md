依据：`docs/specs/v3.5.2-raw-stream-artifacts-requirements.md`、`docs/specs/v3.4-stream-reliability-requirements.md`、`docs/specs/v3.5-agent-context-requirements.md`、`cairn/tests/e2e_test.md`

## 0. 目标边界

目标：把完整 raw stdout/stderr/worker JSONL 从主 DB 移出，落到 run log/artifact 文件；`execution_events` 保留语义事件、terminal/session/tool/message、bounded raw preview/ref/metric，从而压低 SQLite 体积并保持功能等价。

与 v3.5 agent context 关系：

- 命名为 v3.5.2，便于与 v3.5 agent context 合并实现。
- 最终只跑一次 E2E，同时覆盖 agent context 注入与 raw stream artifact 化。

SSOT 生命周期：

- 当前 Pending marker：`v3.5.2-raw-stream-artifacts`。
- 实现完成后，SSOT 主体需改写 raw stdout/stderr 边界：完整 raw 不再是主 DB 承诺，DB raw event 只是 preview/ref。

复杂度：architecture-or-runtime。触及 EventSink、run log/artifact、Pi projector、server event payload、UI Raw view、DB cleanup、E2E。

## Phase 0: Contract First 与测试基线

### 目的

先把“功能等价”和“DB 小”的合同写成测试。

### 步骤

1. 定义 raw artifact contract：
   - `execution_id`
   - `project_id`
   - `run_log_id`
   - `path`
   - `size_bytes`
   - `sha256`
   - `streams`: stdout/stderr byte counts
   - API-visible ref location: artifact id or `execution_runs.metadata_json.raw_stream`
2. 定义 DB raw preview event contract：
   - `payload.text` 是 preview。
   - `payload.preview = true`
   - `payload.truncated`
   - `payload.omitted_bytes`
   - `payload.raw_ref`
   - `payload.sanitised`
3. 定义预算：
   - 每 execution stdout preview <= 16 KiB。
   - 每 execution stderr preview <= 16 KiB。
   - 单条 preview <= 4 KiB。
   - 对足够大的 raw stream，DB raw persisted/original < 0.25。
   - 单 execution `stdout/stderr` payload_json 总量 < 48 KiB，作为集成与 E2E 硬门槛。
4. 新增 fixture：
   - Pi JSONL 包含巨大 `agent_end.messages`。
   - 仍需要 projector 从 full input 中得到 final assistant。
5. 增加 DB helper：
   - 统计某 execution raw `stdout/stderr` payload_json bytes。
   - 统计 semantic `message` 是否包含完整首尾文本。
   - 统计 raw bytes seen、run log bytes、DB persisted raw bytes、persisted/original。
6. 增加 session/branch equivalence helper：
   - 验证 `session_action == "resume_continue"`。
   - 验证 `remote_session_in_id == source_execution.remote_session_out_id`。
   - 验证 resume 进入 source/main Output history。
   - 验证 fork/branch continue 使用 branch-local latest session，且不污染 main history。
7. 增加 cursor pagination helper：
   - 用小 `limit` 遍历 execution events。
   - 验证 semantic final assistant 与 terminal status 均可由 endpoint-scoped cursor 读到。

### 测试

- RED：当前实现 raw payload 超预算。
- RED：当前实现 `agent_end.messages` 可完整进入 DB。
- RED：当前 run log/artifact ref 不足以从 execution API 定位完整 raw。
- RED：当前 Pi projector 会在 `_pending_agent_messages` 持有完整 `agent_end.messages`。
- RED：当前 E2E 若只看 Raw/Debug preview，无法证明 Conversation/fork/resume 等价。

### 验收

- 测试明确区分：semantic 完整、raw DB 有界、full raw 文件可定位。

### 审查点

- 不把问题偷换成“Raw view 少显示一点”。
- 不截断 semantic assistant final。

## Phase 1: Raw Stream File Sink / Artifact Ref

### 目的

保证完整 raw stream 有可靠落点，主 DB 只保存指针。

### 步骤

1. 复用 `RunLogWriter` 作为完整 raw stream file sink。
2. 在 run log close 时计算或记录：
   - file path
   - size
   - sha256
   - stdout/stderr bytes seen
3. 将 raw ref 写入 execution metadata，或登记 artifact：
   - 优先 artifact：`type="transcript"` 或 `type="file"`。
   - 若 artifact 接入会牵动过大，先写 `execution_runs.metadata_json.raw_stream`，并在 plan/SSOT 中标记 artifact 化为后续增强。
   - 无论选择 artifact 还是 metadata，execution detail/API 必须能返回 ref。
4. raw ref 不含 API key；path/hash/size 可入 DB。
5. 保持 run log redaction。

### 测试

- Worker run 后 metadata/artifact 能定位 run log。
- Run log 文件存在，sha256/size 与 DB ref 匹配。
- API key 不出现在 run log fixture 输出中。
- Execution API 返回的 raw ref 可解析，不能只在本地 logger 对象内可见。

### 验收

- 完整 raw stream 不靠 `execution_events` 还原。

### 审查点

- 不新增新 DB raw blob 表。
- 文件路径不跨 workspace/security 边界暴露敏感 secret。

## Phase 2: EventSink 三路分发

### 目的

从同一 worker stream 分出 file sink、projector、DB preview/ref 三条职责。

### 步骤

1. 调整 `CompositeRunLogger.write_stream()` 保持完整流进入 run log。
2. 调整 `ExecutionEventSink.write_stream()`：
   - 完整 redacted stream 进入 projector。
   - DB raw preview budgeter 只生成 preview/ref/metric events。
3. 新增 `RawPreviewBudgeter`：
   - per execution + per stream 状态。
   - 超预算后只累计 omitted bytes。
   - close 时写最终 metric event。
4. 预算不影响 `flush_projector_events()`。
5. event_key 保持 deterministic enough for retry；preview/metric event_key 不与 semantic event 冲突。

### 测试

- 大 stdout 只生成小 preview + metric。
- projector fake 接收 full text。
- EventSink finish/retry tests 不回归。
- 长流式 final message 仍在 finish batch 前进入队列。

### 验收

- DB raw payload 降低数量级。

### 审查点

- 不能因 preview budget 让 EventSink queue 更容易 full。

## Phase 3: Pi Raw Preview Sanitiser

### 目的

直接消除 Pi `agent_end.messages` 重复历史入库，并避免 dispatcher 内存重复持有完整历史。

### 步骤

1. 对 DB preview path 增加 Pi JSONL sanitiser。
2. 识别 JSON line：
   - `type == "agent_end"` 且有 `messages` list。
   - 删除 `messages`。
   - 写入 `messages_omitted`、`messages_count`、`messages_omitted_bytes`。
3. Sanitiser 不作用于 projector full input。
4. 若非 Pi worker，可只走通用 preview budget。
5. 改造 `PiStreamProjector`：
   - 删除 `_pending_agent_messages: list[list[dict]]`。
   - 在处理 `agent_end` 时只扫描当次 messages，提取最后 assistant fallback text。
   - 保存 bounded fallback text 或最终 assistant message object 的最小必要表示。
   - 保存 `agent_end_messages_count`、`agent_end_messages_omitted_bytes` 等统计用于诊断。
   - close 时使用该 fallback text 生成 final assistant semantic message。
6. 如果 final assistant 本身非常长，按 semantic message 合同保留完整回答；不得保留历史 user/tool/message 数组。

### 测试

- DB stdout preview 不含 `"messages":[` 大数组。
- Sanitised preview 仍含 `type=agent_end` 与 omitted metadata。
- Pi projector close 可从 full input 得到 assistant fallback。
- Pi projector unit test 断言对象状态不包含完整 historical messages list。
- 大 `agent_end.messages` fixture 下 dispatcher 内存状态只随 final assistant fallback 增长，不随完整历史线性保存。

### 验收

- 用户观测到的主要 DB 膨胀根因被消除，dispatcher 运行期也不再缓存完整重复历史。

### 审查点

- 不破坏 `session`、`message_update`、`tool_execution_*` 投影。

## Phase 4: Server/API/UI Raw View

### 目的

让用户看到 Raw 是 preview，并能定位完整 raw 文件。

### 步骤

1. Execution events API 保持不变。
2. Execution detail API 或 artifact/debug API 暴露 raw stream ref：
   - artifact id 或 metadata path。
   - size/hash。
   - raw bytes seen 与 DB persisted bytes stats。
3. UI Conversation 不变：只消费 semantic events。
4. UI Raw/Debug view：
   - 显示 preview。
   - 显示 truncated/omitted bytes。
   - 显示 raw ref path/artifact id/run_log id。
5. Export 默认只带 raw preview/ref；完整 raw 作为附件/显式 debug 另议。

### 测试

- Conversation projection guard 不显示 raw preview marker。
- Raw view/browser smoke 可见 omitted bytes/ref。
- Export 不含完整 raw JSONL。
- Execution detail API 能返回 raw ref，且 ref 与文件 size/hash 一致。
- Conversation semantic message 不包含 `messages_omitted`、`raw_ref`、`truncated` 等 debug 字段。

### 验收

- 功能等价：用户仍能看对话、查 raw 线索；DB 不保存全文 raw。

### 审查点

- 不新增 `/runs/*/transcript` 主路径。

## Phase 5: Existing DB Cleanup

### 目的

处理当前已膨胀 DB。

### 步骤

1. 新增命令：
   - `cairn db prune-raw-events --db-path <db> --dry-run`
   - `cairn db prune-raw-events --db-path <db> --yes`
   - `cairn db prune-raw-events --db-path <db> --yes --vacuum`
2. Dry-run 输出：
   - raw event count。
   - raw payload bytes。
   - top projects/executions by raw bytes。
   - estimated retained bytes。
3. Apply：
   - 只处理 `stdout`/`stderr` events。
   - 使用同一 sanitise/preview 规则。
   - 保留 event id、seq、project_seq、cursor、event_key。
   - 不修改 semantic events。
   - 保留 projects/executions/message/tool/session/status；用户当前仍想保留的 `proj_004` 必须仍可打开和分页查看。
   - 若直接处理本地真实 DB，先生成备份；更推荐先在 copied DB 上 dry-run/apply/vacuum 验证。
4. Vacuum：
   - checkpoint WAL。
   - 执行 VACUUM。
   - 输出 before/after size 或 page count。

### 测试

- Seed 大 stdout DB，dry-run 报告正确。
- Apply 后 raw payload 下降，cursor 顺序仍可分页。
- Vacuum 后文件大小/page count 下降；若平台差异导致不稳定，至少验证 freelist/page count。
- 对复制的旧 DB 执行 cleanup 后，`proj_004` project row、execution rows 与 semantic events 仍存在，Output/Conversation 可按 cursor 读取。

### 验收

- 用户可把现有 1.3GB DB 安全瘦身。

### 审查点

- 没有 `--yes` 不改数据。
- 不把 cleanup 写进普通 migration。
- 不为了旧 raw blob 引入长期兼容分支；旧库瘦身是显式 maintenance，不污染新主线。

### 目的

### 步骤

1. 按 `cairn/tests/e2e_test.md`：

   - 使用 `dispatch.dev.yaml`。
   - 使用未占用高端口。
   - 准备 `pentestVM` SSH/Pi，不碰 `/home/kali/ctf`。
2. 创建 agent context template：
   - 要求回答包含 `V35-AGENT-CONTEXT-ACTIVE`。
3. 创建 project 时选择并微调 template。
4. 验证 v3.5 materialization 不是“prompt magic”：

   - execution metadata 记录 `agent_context.enabled/kind/content_hash/materialized_path/status`。

5. 发起 Pi fresh/fork/resume questions：
   - 要求输出 320 行。

7. 验证存储：
   - 查询 run log bytes / raw bytes seen。

   - 当 raw stream 足够大时，DB persisted raw bytes / original raw bytes < 0.25。
   - 查询 DB：raw stdout payload 不含完整 `agent_end.messages`。
   - 查询 DB：raw stdout payload 可见 `messages_omitted/messages_count/messages_omitted_bytes` 或 equivalent sanitised metadata。
   - 查询 DB：semantic assistant message 不含 raw preview/truncation/sanitise marker。
   - 查询 DB/API：raw ref/path/hash/size 可见。
   - 查询 run log/artifact 文件：完整 raw stream 文件存在，size/hash 匹配。
8. 验证 cleanup：
   - 插入或生成大 raw stdout event fixture。

## 独立审查摘要

复杂度：architecture-or-runtime。

实际审查：2 个 fresh-context sub-agent。

审查角度：

- 存储边界、运行期内存与 SSOT 一致性。
- E2E 等价性、fork/resume/session/cursor 与 v3.5 共享验收。

已采纳的关键发现：

- 完整 raw JSONL 不应进入主 DB；DB 只保存 semantic events 与 bounded preview/ref/metric，完整 raw 进入 run log/artifact。
- `stdout`/`stderr` event 新语义必须在实施完成后同步 SSOT 主体：它们是 debug preview，不是完整 transcript。
- Raw ref 必须经 artifact 或 `execution_runs.metadata_json.raw_stream` 可解析，并通过 API 暴露。
- Pi projector 也要去重：不能把完整 `agent_end.messages` 放在 `_pending_agent_messages` 中等 close，只保留 final assistant fallback text 与 summary。
- E2E 必须验证 resume/fork 等价、endpoint-scoped cursor 小页翻页、semantic message 不含 raw truncation marker、agent context 真 materialize、DB absolute/relative byte budget、run log 完整证据。

未采纳或降级：

- 未把 artifact 表登记设为首版硬性要求。理由：若 artifact 接入会显著扩大实现面，metadata raw ref 可满足 MVP；但 API 可见与 hash/size 可验证是硬要求。

## 风险与开放问题

- Run log 文件仍会增长；本需求只解决主 DB 膨胀。后续可做 run log retention。
- 没有 semantic projector 的 worker，Conversation 无法从 raw 中完整重建；这是正确暴露 backend adapter 能力，不应让 DB raw 兜底成 transcript parser。
- Artifact 表 type 是否足够表达 raw stream，实施时可能选择先写 execution metadata ref。
