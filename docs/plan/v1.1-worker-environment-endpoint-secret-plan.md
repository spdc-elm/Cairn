# Worker Environment v1.1 Endpoint Secret Plan

依据：`docs/specs/v1-worker-environment-requirements.md`

状态：已执行。真实 SSH/Pi E2E 仍需在本机 server DB 中填入对应 endpoint key 后运行。

核心修正：v1 将 `base_url/provider_api/api_key` 放入 dispatcher profile，过度简化了网络现实。v1.1 改为 server environment 保存 provider endpoint；dispatcher 只保存 model profile 与 worker 调度策略。

## 0. 目标边界

### 必须达成

- server environment 支持 `provider_endpoints[]`。
- endpoint 保存 `id/type/base_url/provider_api/api_key`。
- 普通 API/UI 永不返回明文 API key。
- dispatcher config 使用 `model_profiles[]`，不再使用 `profiles[]`。
- worker 使用 `model_profile` 与 `endpoint`。
- dispatcher 运行时用 `model_profile + server endpoint` resolve driver env。
- `dispatch.example.yaml`、`dispatch.dev.yaml`、`dispatch.local.yaml` 全部迁移到 v1.1 schema。

### 明确不做

- 不做 v1 schema 兼容。
- 不做完整 Vault/keychain。
- 不做多用户 RBAC。
- 不做 endpoint snapshot。

## Phase 0: Schema Contract 与 Secret 护栏

### 步骤

1. 定义 endpoint 数据模型：
   - `id`
   - `type`
   - `base_url`
   - `provider_api`
   - `api_key`
   - `created_at`
   - `updated_at`

2. 定义 public/redacted 模型：
   - `has_api_key`
   - `api_key_preview`
   - 不包含 `api_key`

3. 定义 upsert 语义：
   - create 时可写 `api_key`
   - update 时 `api_key: null` 或空字段表示保留旧 key
   - `clear_api_key: true` 表示删除 key

4. 确认 secret redaction helper 覆盖：
   - exact key
   - `Authorization: Bearer ...`
   - JSON `apiKey`
   - startup healthcheck preview
   - run log stream

### 测试

```bash
uv run --project cairn python -m unittest discover -s cairn/tests -p '*endpoint*' -v
uv run --project cairn python -m unittest discover -s cairn/tests -p '*redaction*' -v
```

### 验收

- public endpoint response 无明文 key。
- error/report/log 中无 key。

## Phase 1: Server DB 与 API

### 步骤

1. 修改 `cairn/src/cairn/server/db.py`。
   - 新增 `environment_provider_endpoints` 表，或在 `work_environments` 中新增 `provider_endpoints_json`。
   - MVP 建议独立表，便于 CRUD、唯一约束与 redaction。
   - 唯一约束：`(environment_id, endpoint_id)`。

2. 修改 `cairn/src/cairn/server/models.py`。
   - 增加 `ProviderEndpointPublic`。
   - 增加 `ProviderEndpointUpsert`。
   - `WorkEnvironmentPublic` 增加 `provider_endpoints: list[ProviderEndpointPublic]`。

3. 修改 `cairn/src/cairn/server/services.py`。
   - endpoint row -> public redacted。
   - endpoint secret 读取仅用于 dispatcher 内部路径。
   - key preview 只显示短片段。

4. 修改 `cairn/src/cairn/server/routers/environments.py`。
   - environment create/update 支持内嵌 endpoint。
   - 或新增：
     - `GET /environments/{id}/endpoints`
     - `POST /environments/{id}/endpoints`
     - `PUT /environments/{id}/endpoints/{endpoint_id}`
     - `DELETE /environments/{id}/endpoints/{endpoint_id}`
   - dispatcher secret 路径可为：
     - `GET /environments/{id}/endpoints/{endpoint_id}?include_secret=true`
   - 普通 UI/API 默认 `include_secret=false`。

### 测试

新增：

```text
cairn/tests/server/test_environment_endpoints_v11.py
cairn/tests/server/test_endpoint_secret_redaction.py
```

覆盖：

- 创建 endpoint 后 DB 有 key。
- 普通 GET 不返回 key。
- include_secret 路径返回 key。
- update 不带 key 保留旧 key。
- `clear_api_key` 删除 key。
- 删除 environment 后 endpoint 级联删除。

### 验收

- server 可保存 endpoint。
- UI/API 不泄露 key。

## Phase 3: Dispatcher Config v1.1

### 步骤

1. 修改 `cairn/src/cairn/dispatcher/config.py`。
   - `ProfileConfig` 改名或语义改为 `ModelProfileConfig`。
   - 顶层字段：`model_profiles[]`。
   - `ModelProfileConfig` 只允许：
     - `id`
     - `type`
     - `model`
     - `context_window`
   - `WorkerConfig`：
     - 删除 `profile`
     - 新增 `model_profile`
     - 新增 `endpoint`
   - 非 mock worker 必须声明 `model_profile` 与 `endpoint`。
   - mock worker 可省略两者。

2. 删除 dispatcher config 中 endpoint secret 字段：
   - `base_url`
   - `provider_api`
   - `api_key`

3. 更新 config loader 错误信息，避免 Pydantic input 泄露。

### 测试

## Phase 4: Endpoint Resolution

### 步骤

1. 修改 dispatcher server client。
   - 新增读取 environment endpoint secret 的方法。
   - 普通 environment refresh 只拉 redacted metadata。

2. 建立 helper：

```text
resolve_worker_env(worker, model_profile, provider_endpoint) -> dict[str, str]
```

映射：

- Pi:
  - `PI_MODEL`
  - `PI_BASE_URL`
  - `PI_PROVIDER_API`
  - `PI_API_KEY`
  - optional `PI_MODEL_CONTEXT_WINDOW`
- Codex:
  - `CODEX_MODEL`
  - `CODEX_BASE_URL`
  - `OPENAI_API_KEY`
  - optional `CODEX_HEALTHCHECK_STREAM`
- ClaudeCode:
  - `ANTHROPIC_MODEL`
  - `ANTHROPIC_BASE_URL`
  - `ANTHROPIC_AUTH_TOKEN`

3. Worker selection 增加 endpoint 可用性判断。
   - environment 不含 worker.endpoint -> worker 对该 environment 不可用。
   - 不回退其它 endpoint。

4. run metadata 记录：
   - worker
   - model_profile
   - model
   - endpoint id
   - environment id
   - workspace
   - 不记录 api_key

### 测试

新增：

```text
cairn/tests/dispatcher/test_endpoint_resolution_v11.py
cairn/tests/dispatcher/test_worker_selection_endpoint_v11.py
```

覆盖：

- Pi env resolve 正确。
- endpoint 缺 key 时 startup healthcheck 失败且 redacted。
- worker endpoint 缺失时不可调度。
- 同一 worker 在两个 environment 上同名 endpoint 解析出不同 base_url/key。

## Phase 5: Healthcheck

### 步骤

1. Server environment healthcheck：
   - 地点检查仍在 server。
   - endpoint 检查只判断配置完整性，或做 provider 支持的 model-free connectivity check。
   - 不做 model-specific completion。

2. Dispatcher startup healthcheck：
   - 展示 `environment + endpoint + worker + model_profile` 矩阵。
   - 用 server endpoint secret 做真实模型 ping。
   - 所有输出 redacted。

### 验收

- 地点失败、endpoint 缺 key、模型失败三类原因可区分。
- endpoint 修改后无需重启 dispatcher 即影响后续任务。

1. 启动 server。
2. 在 Web UI 创建 SSH environment。
3. 在该 environment 下创建 endpoint：
   - id: `pi-GPT5.4`

   - provider_api: `openai-completions`

4. 创建 project 绑定该 environment。
5. 启动 dispatcher：

```bash

```
