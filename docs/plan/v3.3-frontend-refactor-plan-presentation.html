V3.3 Plan: 换框架，但先钉契约

前端重构的目标不是现代化外观，而是把 UI 从全能脚本改成薄渲染层：server 给稳定 projection，React/TypeScript 消费它，reducer 与 browser smoke 证明 Graph、Output、Ask、Log 的锚点一致。

拒绝

只拆 Alpine 大文件

短期改动小，但 selection、stream、Ask lifecycle 仍难测试，容易从一个大 store 变成多个隐形大 store。

采用

React + TypeScript + Vite

组件边界、类型契约、Vitest、Playwright 更适合当前复杂交互面。Cytoscape 作为 imperative island 封装。

约束

不破坏 cairn serve

npm 只作开发与构建依赖。生产静态产物仍由 FastAPI 托管，迁移期保留 legacy fallback。

目标架构

Server Projection /ui-projection owns runtime status, capability, provenance, timeline input.
ApiClient HTTP, JSON/text, errors, AbortSignal, no product semantics.
Reducers Selection, graph elements, conversation view, polling, question availability.
React Panes ProjectList, Detail, Output, Ask, Timeline, Settings, Environment.
GraphCanvas Cytoscape init, layout, highlight, resize; semantic events only.
关键取舍
  • React 不是第一步；/ui-projection contract 与 reducer tests 先行。
  • Build output 放入 server/static/app，保证 Python-only 运行体验。
  • /graph 降为 alias，新代码统一使用 /ui-projection。
  • Raw fallback 保留，但不得成为 Conversation 主事实源。
失败红线
  • Graph 与 Output 锚到不同 execution。
  • UI 继续按 worker type 判断 fork/resume。
  • 主路径调用 /questions 或 /runs/*/transcript。
  • 需要单独前端 dev server 才能使用生产 UI。

阶段路线

0

Contract First

新增 ProjectUiProjection 与 TestClient contract tests；建立 frontend test scaffold；legacy fallback 保留。

1

React/Vite Shell

建立 cairn/frontend，Vite build 到 server/static/app，FastAPI 返回新 shell。

2

Typed Domain Core

API client、contracts、graph builder、selection reducer、conversation mapper、question availability、polling reducer。

3

Graph 工作面

ProjectList、ProjectShell、GraphCanvas、Detail、Timeline；先证明 selection parity。

4

Output / Ask

ExecutionStream cursor、Messages/Tools/Raw、Fork/Resume/Fresh Context、resume timeline merge。

5

剩余面板与视觉

Environment、Settings、Hints、Replay；桌面/窄屏 visual smoke，canvas pixel check。

6

Cutover

React UI 成为主路径；architecture guards 禁 legacy API；README 与 CI/local validation 补齐。

验收
  • ProjectList、Graph、Detail、Output、Ask、Log、Settings、Hints、Environment、Replay 能力不退。
  • Browser E2E 覆盖 running output、missing provenance、fork 两轮、resume 确认、healthcheck、replay。
  • Visual smoke 覆盖空/有项目、小/多节点 graph、running Output、Ask、Environment、Replay。
开放
  • 建议提交 production build artifact，保证包内 UI 可用。
  • E2E 默认用 seeded DB 与 mock events；真实 dispatcher/worker 留作 manual E2E。
  • Legacy fallback 至少保留到 React browser smoke 全绿。
