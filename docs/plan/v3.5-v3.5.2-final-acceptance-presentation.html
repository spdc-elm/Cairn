最终只验结果

V3.5 agent context 与 V3.5.2 raw storage 共用一轮 E2E。实现过程由工程侧自行取最优，只要达到这里的可观测效果。

验收口径

AGENTS.md 真生效 创建 template，创建 project 时选择并微调 snapshot。执行时远端 workspace 出现 Cairn-managed AGENTS.md，Pi enabled run 不带 --no-context-files，回答包含 context 标记。
Conversation 功能等价 fresh、fork、branch continue、resume 都正常。长流式 320 行首尾可见，terminal status 可见，小 limit cursor 分页也不漏 final assistant。
DB 不再存 raw 仓库 execution_events 只保存 semantic events 与 bounded raw preview/ref。完整 raw JSONL 在 run log/artifact，API 能定位 path/hash/size。

必须达到的数值

< 48 KiB单 execution 的 DB stdout/stderr payload 总量。
< 0.25大 raw stream 场景下 DB raw persisted / original raw bytes。
0DB 中完整 agent_end.messages 数组。
100%message/tool/session/status semantic events 可分页读回。

一轮 E2E 怎么验

主流程

测试 DB 高端口 server dispatcher pentestVM Pi
  • 创建 agent context template，内容要求输出 V35-AGENT-CONTEXT-ACTIVE。
  • 创建 project，选择 template 并微调 snapshot。
  • 跑 fresh execution，确认 session out、context metadata、远端 AGENTS.md。
  • 跑 fork 长输出，要求 V352-LONG-STREAM-001 到 V352-LONG-STREAM-320。
  • 跑 branch continue，确认使用 fork branch 最新 session。
  • 跑 resume，确认进入 source/main Output，且 fork 内容不污染 main history。

必须查证据

  • API/DB 查 execution metadata：agent context hash/path/status 存在。
  • DB 查 semantic message：包含 context token 与长输出首尾。
  • DB 查 stdout/stderr preview：小于预算，含 omitted/ref，不含完整 messages 数组。
  • run log/artifact 文件存在，size/hash 与 API ref 一致。
  • Raw/Debug 只显示 preview/ref；Conversation 不出现 truncation/debug marker。

旧 DB 处理

保留什么

  • 保留当前有价值 project，例如 proj_004。
  • 保留 execution、message、tool、session、status semantic events。
  • 保留 event id、cursor、seq、event_key，旧 Output/Conversation 还能分页。

清理什么

  • 只裁剪旧 stdout/stderr raw payload。
  • 先 dry-run，确认 raw bytes 与 top executions。
  • apply 后可 VACUUM，验证 DB file/page count 下降。
  • 这是一次性 maintenance，不为旧 raw blob 做长期兼容分支。

失败判定

不能接受

  • 回答对了，但远端没有 Cairn-managed AGENTS.md。
  • DB 仍保存完整 Pi agent_end.messages。
  • 长输出在 UI 看似完整，但小页 cursor 读不到 final/status。
  • resume 混进 fork history，或 fork 污染 main history。

通过定义

  • 一轮 E2E 覆盖 v3.5 与 v3.5.2。
  • 功能语义等价，DB raw 增长受控。
  • 完整 raw 仍可通过 run log/artifact 取证。
  • 旧 DB 可瘦身且 proj_004 仍可用。
