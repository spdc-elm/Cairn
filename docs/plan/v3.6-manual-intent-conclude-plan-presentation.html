V3.6 Manual Intent Conclude

目标：当 worker/API 卡住或 execution 已 failed 时，用户仍能保住已完成工作：手动 conclude，并继续 fork/resume 可用 session。

日期 2026-05-23 状态 待执行计划 范围 Server API / Web UI / Conversation policy 约束 不停止 server / dispatcher

核心路径

1. Stuck Intentactive 或 latest failed execution 仍关联 intent。
2. Copy PromptUI 提供 conclude prompt，用于外部 resume。
3. Resume SessionAI 停止探索，产报告，返回 JSON。
4. Paste JSONServer 解析 wrapped/bare JSON。
5. Write Factatomic claim，fact + evidence，terminal barrier。

架构边界

  • Intent 不承载 live worker lease。
  • active state 来自 execution_runs 派生。
  • manual conclude 是用户导入 conclusion，不是 dispatcher 自动路径。
  • failed/cancelled execution 只要 session available，仍可作为 fork/resume source。
  • unhealthy runtime health 只作为 warning，不阻止 user-initiated branch。

风险

需要守住的点

  • 不要让 Intent.worker 重新变成 live state。
  • 不要把 dispatcher-only conclusion API 暴露成 UI 主路径。
  • manual conclude 与 dispatcher late finish 可能竞争，必须测试 benign 409。
  • duplicate/concurrent manual submit 必须只有一个 primary fact。
  • source execution provenance 必须 same project + same intent。
完成定义

Done

  • stale worker 不再造成 no-active-execution 的误导路径。

  • 完整 E2E 覆盖 API、浏览器 UI、failed conversation 与长流式输出。
  • 测试后关闭本轮启动的监听服务，并证明未触碰已有服务。
