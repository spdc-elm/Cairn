# V3.2 Live Conversation Thread Execution Plan

依据：`docs/specs/v3.2-live-conversation-thread-requirements.md`
日期：2026-05-20
状态：待确认执行计划，已吸收多角度架构审查

## 0. 目标边界

### 0.1 核心判断

V3.2 不是“给 Output 补轮询”，而是把运行层事实源从 `run_provenance + question_jobs + question_events + intent heartbeat` 收束为：

```text
Fact/Intent DAG        用户与产品本体
ExecutionRun           worker 一次运行、lease、session、终态
ExecutionEvent         stdout/stderr/message/tool/status/session 的实时事件流
Branch                 fork/resume/fresh_context 的 session 连续线
Artifact/EvidenceLink  report、transcript、文件、证据关系
```

但实现顺序不能先删库。当前 dispatcher、UI、server 都仍依赖旧 lease 与 question/runtime 路径。若 Phase 1 直接 destructive reset，会产生不可运行中间态。

执行策略改为：

```text
先 additive 建 ledger 和 RED 护栏
再让旧流程双写 ExecutionEvent
再逐 task 迁到 ExecutionRun lease
再用 Branch 替换 question runtime
最后 destructive cleanup / reset
```

这里的 `claim/lease` 只作为内部运行时动词使用，不是新的产品本体，也不引入 `Claim` 表或用户概念。

### 0.2 架构契约

Server owns semantic graph and execution ledger persistence. Dispatcher never writes the DB and never calls project graph mutation APIs directly. Dispatcher may only report runtime facts through dispatcher-scoped APIs: lease/patch execution, append execution events, upload artifacts, and submit conclude requests. Server validates those requests and performs all Fact/Intent/EvidenceLink mutations transactionally.

边界要求：

- Server 管 project、Fact/Intent DAG、ExecutionRun/Event 持久化、Branch、Artifact、API。
- Dispatcher 管 runtime、worker driver、environment execution、stdout/stderr streaming、event 上报。
- Server 不 import dispatcher runtime、environment、driver，不读取 worker secret 来执行 worker。
- Dispatcher 不直接调用语义图写 API，例如 create intent、patch intent、complete project、旧 conclude。
- 共享 parser / DTO 必须放 `cairn.shared.*` 或 `cairn.worker_events`，不得让 dispatcher import `cairn.server.*`。
- Worker capability 由 dispatcher 发布到 inventory；server 只读 capability，不硬编码 Codex/Pi/Claude 能力。
- `worker_runtime_health` 继续作为 availability read model。`ExecutionRun(task_type='healthcheck')` 记录一次检查的审计事件，不替代健康矩阵；dispatcher 仍通过健康上报 API 更新 read model，server 统一用 inventory + runtime health + source execution identity 判定 Fork/Resume 可用性。

### 0.3 必须达成

- Running Output 未结束时即可按 cursor 读取 events，刷新后继续追。
- 普通 explore/conclude/reason/question/healthcheck 均落为 `execution_runs`。
- stdout/stderr/message/tool/status/session 的 UI 主路径来自 `execution_events`。
- `Intent` 只表达 work order；live lease、heartbeat、cancel/retry 在 `ExecutionRun`。
- successful concluded exploration intent 恰有一个 primary result fact。
- Pi / Claude Code 支持 headless fork continuation；Codex 当前 inventory 应声明 headless fork unavailable，UI 只渲染 server projection 的 reason。
- Resume 并发受 server-owned session lock 保护。
- 最终 fresh v3.2 schema 无 `run_provenance`、`question_*`、intent live lease 字段。

### 0.4 明确不做

- 不引入 `Claim` 核心概念。
- 不做 Codex PTY/TUI fork 自动化。
- 不把远端 CLI 原生 session 文件同步回 Cairn DB。
- 不把所有 worker output 自动变成 fact。
- 不把 JSONL 继续作为 UI source of truth；它最终只能是 artifact/debug mirror。

## Phase 1: Additive Execution Ledger Schema 与 API

### 目的

先在现有系统旁边建立 `ExecutionRun/Event/Branch/Artifact`，不立即删除旧表，让系统在迁移过程中可运行。

### 范围

```text
cairn/src/cairn/server/schema.py
cairn/src/cairn/server/db.py
cairn/src/cairn/server/migrations/runner.py
cairn/src/cairn/server/models.py
cairn/src/cairn/server/services.py
cairn/src/cairn/server/routers/executions.py
cairn/src/cairn/server/routers/branches.py
cairn/src/cairn/server/app.py
cairn/src/cairn/shared/api_models.py
```

### 步骤

1. 新增 additive migration `0008_execution_ledger.py`。此 migration 只加新表，不删旧表。

2. 给图层补最小 provenance 字段：

```text
intents.concluded_fact_id TEXT NULL
facts.kind TEXT CHECK IN ('origin','goal','fact','observation','negative_result')
facts.status TEXT CHECK IN ('active','superseded','retracted')
facts.produced_by_execution_id TEXT NULL
facts.produced_by_intent_id TEXT NULL
```

约束：

- successful concluded exploration intent 必须在同一 transaction 内写 `facts.produced_by_execution_id`、`facts.produced_by_intent_id`、`intents.concluded_fact_id`。
- `concluded_fact_id` 指向 primary result fact；细粒度观察不拆成多 fact。
- Phase 1 为过渡 additive，可先 nullable；Phase 6 fresh schema 再收紧 NOT NULL / FK / uniqueness。

3. 新增 `execution_runs`：

```text
id TEXT PRIMARY KEY
project_id TEXT NOT NULL REFERENCES projects(id)
intent_id TEXT NULL
branch_id TEXT NULL
parent_execution_id TEXT NULL
task_type TEXT CHECK IN ('explore','conclude','reason','question','healthcheck')
phase TEXT CHECK IN ('bootstrap','run','followup','healthcheck')
session_action TEXT CHECK IN ('fresh_context','fork_initial','resume_continue','branch_continue') NULL
worker_name TEXT NULL
worker_type TEXT NULL
environment_id TEXT NULL
endpoint_id TEXT NULL
model_profile_id TEXT NULL
workspace TEXT NULL
status TEXT CHECK IN ('pending','leased','running','succeeded','failed','cancelled')
leased_by TEXT NULL
leased_at TEXT NULL
lease_expires_at TEXT NULL
last_heartbeat_at TEXT NULL
control_state TEXT CHECK IN ('normal','conclude_requested','abort_requested')
control_requested_at TEXT NULL
control_reason TEXT NULL
remote_session_in_kind TEXT NULL
remote_session_in_id TEXT NULL
remote_session_in_status TEXT NULL
remote_session_out_kind TEXT NULL
remote_session_out_id TEXT NULL
remote_session_out_status TEXT NULL
input_snapshot_json TEXT NULL
started_at TEXT NULL
finished_at TEXT NULL
returncode INTEGER NULL
error_code TEXT NULL
error_detail TEXT NULL
metadata_json TEXT NULL
created_at TEXT NOT NULL
updated_at TEXT NOT NULL
```

字段 ownership：

- `worker_name/worker_type/environment_id/endpoint_id/model_profile_id/workspace` 只能由 dispatcher lease/patch 写入。`POST /projects/{project_id}/executions` 不接收这些字段。
- 这些 worker identity 字段是 opaque audit labels；server 可用它们与 inventory/health 做匹配判定，但不得用它们解析 secret 或构造 worker 命令。

合法归属矩阵：

```text
task_type    required owner                         legal phase
explore      intent_id, except project bootstrap     bootstrap|run
conclude     intent_id                               run
question     branch_id                               followup
reason       project_id only                         run
healthcheck  project_id + execution identity labels  healthcheck
```

`ExecutionRun` 不允许无主垃圾桶：除 `reason/healthcheck` 这种 project/system scoped run 外，必须有 `intent_id` 或 `branch_id`。`parent_execution_id` 只表达 retry/conclude child 等机械运行关系；conversation/session lineage 只归 Branch 表达。

4. 新增 `execution_events`：

```text
id TEXT PRIMARY KEY
execution_id TEXT NOT NULL REFERENCES execution_runs(id)
project_id TEXT NOT NULL REFERENCES projects(id)
seq INTEGER NOT NULL
project_seq INTEGER NOT NULL
cursor TEXT NOT NULL
ts TEXT NOT NULL
event_type TEXT CHECK IN ('status','stdout','stderr','message','tool','artifact','fact_candidate','session','metric')
role TEXT NULL
payload_json TEXT NOT NULL
event_key TEXT NULL
created_at TEXT NOT NULL
UNIQUE(execution_id, seq)
UNIQUE(execution_id, event_key) WHERE event_key IS NOT NULL
UNIQUE(project_id, project_seq)
UNIQUE(project_id, cursor)
```

索引：

```text
idx_execution_events_execution_project_seq(execution_id, project_seq)
idx_execution_events_project_seq(project_id, project_seq)
idx_execution_runs_project_intent_created(project_id, intent_id, created_at DESC)
idx_execution_runs_project_branch_created(project_id, branch_id, created_at)
idx_execution_runs_project_status_lease(project_id, status, lease_expires_at)
```

5. Event cursor 分配：

- 新增 project-level counter，例如 `scoped_counters(project_id, kind='execution_event')`。
- append event 与 counter increment 必须在同一 DB transaction。
- 禁止用 `SELECT MAX(project_seq)+1`。
- `cursor = evt_<project_seq>`。
- `status` 与 session 的 canonical value 在 `execution_runs` 行上；`status/session` events 只用于 timeline/audit。任何 row patch 若需要写对应 event，必须在同一 transaction 内完成。
- `fact_candidate` event 只是 payload 类型，不拥有 status、review lifecycle、API 或表；promotion 后才可能成为 Fact/Intent。

6. 新增 `branches`、`artifacts`、`evidence_links`、`execution_session_locks`：

```text
branches:
id TEXT PRIMARY KEY
project_id TEXT NOT NULL
source_execution_id TEXT NULL
parent_branch_id TEXT NULL
anchor_kind TEXT NULL
anchor_id TEXT NULL
mode TEXT CHECK IN ('source','resume','fork','fresh_context')
status TEXT CHECK IN ('active','archived')
created_at TEXT NOT NULL
updated_at TEXT NOT NULL

artifacts:
id TEXT PRIMARY KEY
project_id TEXT NOT NULL
produced_by_execution_id TEXT NULL
type TEXT CHECK IN ('report','transcript','scan','file','screenshot','other')
uri TEXT NULL
path TEXT NULL
content_hash TEXT NULL
summary TEXT NULL
metadata_json TEXT NULL
created_at TEXT NOT NULL

evidence_links:
id TEXT PRIMARY KEY
project_id TEXT NOT NULL
fact_id TEXT NOT NULL
artifact_id TEXT NULL
execution_id TEXT NULL
relation TEXT CHECK IN ('supports','contradicts','derived_from')
created_at TEXT NOT NULL
CHECK (artifact_id IS NOT NULL OR execution_id IS NOT NULL)
FOREIGN KEY (fact_id, project_id) REFERENCES facts(id, project_id)
FOREIGN KEY (artifact_id) REFERENCES artifacts(id)
FOREIGN KEY (execution_id) REFERENCES execution_runs(id)

execution_session_locks:
project_id TEXT NOT NULL
remote_session_kind TEXT NOT NULL
remote_session_id TEXT NOT NULL
execution_id TEXT NOT NULL
branch_id TEXT NULL
lease_expires_at TEXT NOT NULL
created_at TEXT NOT NULL
PRIMARY KEY(project_id, remote_session_kind, remote_session_id)
```

Branch 不持久化 `current_session`、endpoint、model profile 或 workspace。session 与 execution identity 从 source/latest successful execution 推导；若 UI 需要展示 worker identity，由 projection 读取 execution row。`EvidenceLink` 只是 link table，不是新的用户图节点。

7. API 分清创建与 lease：

```http
POST /projects/{project_id}/executions
POST /dispatcher/executions/lease
POST /dispatcher/intents/{intent_id}/lease-execution
PATCH /dispatcher/executions/{execution_id}
POST /dispatcher/executions/{execution_id}/events
GET /projects/{project_id}/executions/{execution_id}
GET /projects/{project_id}/executions/{execution_id}/events?after_cursor=...
```

语义：

- `POST /projects/{project_id}/executions` 创建 pending execution，不 lease。
- `POST /dispatcher/executions/lease` 只 lease 既有 pending execution。
- `POST /dispatcher/intents/{intent_id}/lease-execution` 是 scheduler 原子操作：server 在 transaction 内从 open intent 创建 execution 并 lease。
- 是否允许同一 intent 并发不是 ontology 约束，而是 scheduler policy。默认 policy 可拒绝同一 `intent_id + task_type + phase` 的 active execution；需并行时显式 `allow_parallel=true` 或不同 phase/worker。

8. Graph projection 先只读：

```http
GET /projects/{project_id}/graph
```

返回 facts/intents/hints，并为每个 intent 派生：

```text
active_execution_id
latest_execution_id
runtime_status
worker_name
last_heartbeat_at
```

## Phase 2: Event Sink、Shared Worker Events 与双写

### 目的

把实时 stdout/stderr/session/message 变成 `ExecutionEvent`，但先保持 JSONL mirror，降低迁移风险。

### 范围

```text
cairn/src/cairn/shared/worker_events.py
cairn/src/cairn/shared/worker_event_backends/*
cairn/src/cairn/shared/api_models.py
cairn/src/cairn/dispatcher/runtime/process.py
cairn/src/cairn/dispatcher/runtime/run_logs.py
cairn/src/cairn/dispatcher/runtime/environments/{docker.py,ssh.py}
cairn/src/cairn/dispatcher/tasks/common.py
cairn/src/cairn/dispatcher/protocol/client.py
cairn/src/cairn/server/transcripts/parsers/*  (迁移源，不能继续作为主路径)
cairn/src/cairn/server/transcripts/models.py   (迁移源，不能继续作为主路径)
```

### 步骤

1. 把 transcript/parser normalization 从 `cairn.server.transcripts` 抽到共享事件层：

```text
cairn.shared.worker_events
cairn.shared.worker_event_backends.*
```

约束：

- `cairn.shared.worker_events` 只放通用 DTO、event schema、cursor/batch payload、redacted payload helper，可被 server 和 dispatcher import。
- Codex/Pi/Claude raw-stream normalizer 放 `cairn.shared.worker_event_backends.*` 或 dispatcher adapter 内；server 主路径不得 import backend-specific normalizer。
- 共享层不 import DB、FastAPI、dispatcher environment、driver secret。

2. 新增 `ExecutionEventSink`：

- batching：默认 250ms 或 N 条 flush。
- retry：server 短暂失败时保留 memory queue。
- redaction：沿用 worker secrets。
- durable spool：写入本地 JSONL mirror 后再上报 server。dispatcher crash 后可从 mirror 读取未确认 batch 重放；UI 仍不直接读 mirror。
- terminal 前强制 flush；flush 失败则 patch execution `error_code='event_flush_failed'` 或 terminal metadata。

3. `run_worker_process(...)` 支持双写：

- 启动时 append `status: running` event。
- stdout/stderr chunk 到达时立即 append event。
- worker-native JSON/stream chunk 经 dispatcher/backend normalizer 变成 `message/tool/session` event。
- JSONL mirror 仍写，但只作为 debug artifact，不再作为 UI 主事实源。

4. 新增 `JsonlMirror`：

- 复用旧 `RunLogWriter` 的文件写能力。
- mirror path 写为 `Artifact(type='transcript')`。
- 不再用 JSONL id 定义 execution identity。

## Phase 3: Dispatcher Lease Lifecycle 逐 Task 迁移

### 目的

把 dispatcher 的运行时 lease 从 intent/project/question 表迁到 `ExecutionRun`。

### 范围

```text
cairn/src/cairn/dispatcher/protocol/client.py
cairn/src/cairn/dispatcher/runtime/heartbeat.py
cairn/src/cairn/dispatcher/tasks/{bootstrap,explore,reason,questions,common}.py
cairn/src/cairn/dispatcher/scheduler/loop.py
cairn/src/cairn/dispatcher/models.py
cairn/src/cairn/dispatcher/contracts.py
cairn/src/cairn/dispatcher/output_parser.py
cairn/src/cairn/dispatcher/prompting.py
```

### 步骤

1. `CairnClient` 新增并迁移到 dispatcher-scoped APIs：

```text
lease_intent_execution(...)
lease_pending_execution(...)
heartbeat_execution(...)
append_execution_events(...)
patch_execution(...)
upload_execution_artifact(...)
submit_execution_conclusion_report(...)
```

对应 dispatcher-scoped API：

```http
POST /dispatcher/executions/{execution_id}/artifacts
POST /dispatcher/executions/{execution_id}/conclusion-report
```

`artifacts` 只接收 runtime artifact metadata/content location。`conclusion-report` 只接收 worker 产出的 conclusion text、title、artifact refs、confidence/metadata。server 在 transaction 内创建/更新 Fact、Intent、EvidenceLink；dispatcher 不直接 create fact/intent/hint。

删除或禁用旧语义图写方法：

```text
create_intent
patch_intent
complete
heartbeat(intent)
release(intent)
claim_reason / reason_heartbeat / release_reason
upsert_run_provenance / patch_run_provenance / update_run_session
claim_question_job / start_question_job / append_question_events / finish_question_job
old intent conclude endpoint
```

2. `HeartbeatLease.for_execution(...)`：

- heartbeat 只 patch execution。
- heartbeat response 可携带 control state。
- heartbeat 失败按既有策略 cancel process。

3. 中间态兼容门槛：

- Phase 3 不能先删除旧 question/runtime client 方法再等 Phase 4/5。必须先有 Branch/message pending execution API，或提供旧 `/questions` 到 Branch/execution 的 facade。
- `/projects` 与现有 UI 所需的 running/unclaimed projection 必须在 Phase 3 同步改为从 `execution_runs` 派生；否则继续 mirror 旧 `intents.worker/projects.reason_*` 字段到 Phase 5。
- 每个小阶段完成后，现有 UI 仍能打开 project、看到 running state、发起 Ask/Fresh 或得到明确不可用 reason。

4. 分阶段迁 task：

- 3A bootstrap/explore：从 `lease_intent_execution` 开始，`RunningTask` 保存 `execution_id`。
- 3B reason：不再写 `projects.reason_*`，改为 `ExecutionRun(task_type='reason')`。
- 3C conclude fallback：创建 child execution，`task_type='conclude'`，`parent_execution_id=<explore execution>`。
- 3D healthcheck：独立 `ExecutionRun(task_type='healthcheck')`，graph projection 默认隐藏。
- 3E question：只 claim pending `task_type='question'` execution。若 Phase 4 Branch API 未完成，则旧 `/questions` facade 必须先把 message 映射为 branch question execution。

5. Health read model 责任：

- healthcheck execution 保存 stdout/stderr/status/session 等审计事件。
- dispatcher 仍上报 `worker_runtime_health`；server 在同一 availability service 中读取它。
- healthcheck 成功清除同 execution identity 的 unhealthy block，失败写 redacted detail。
- `unknown` 不阻塞普通调度；明确 `unhealthy` 且未过 `disabled_until` 时禁用对应 execution identity 的 Fork/Resume 与自动调度。

6. Conclude fact 责任：

- 不说 “successful explore execution 自动产 fact”。
- 规则改为：每个 concluded intent 恰有一个 primary result fact。
- `submit_execution_conclusion_report` 由 server 单事务写 Fact、Intent、EvidenceLink；`produced_by_execution_id` 指向真正执行 conclusion 的 execution。
- parent explore execution 与 report artifact 通过 `EvidenceLink` 关联到 fact。

7. Intent 并发策略：

- ontology 允许同一 intent 有多 execution。
- scheduler 默认拒绝同一 `intent_id + task_type + phase` 的 active execution。
- retry / conclude / parallel worker 必须显式区分 phase、worker 或 `allow_parallel`。

## Phase 4: Branch / Conversation 与 Session Lineage

### 目的

用 Branch 替换 question thread，使 resume/fork/fresh_context 成为 branch 下的 execution 序列。

### 范围

```text
cairn/src/cairn/server/routers/branches.py
cairn/src/cairn/server/services.py
cairn/src/cairn/dispatcher/tasks/questions.py
cairn/src/cairn/dispatcher/workers/base.py
cairn/src/cairn/dispatcher/workers/adapters/{pi,claudecode,codex,mock}.py
cairn/tests/server/test_v32_branch_api.py
cairn/tests/dispatcher/test_v32_branch_session_lineage.py
cairn/tests/dispatcher/test_v32_worker_capabilities.py
```

### 步骤

1. Branch 创建 API：

```http
POST /projects/{project_id}/branches
POST /projects/{project_id}/branches/{branch_id}/fork
```

输入：

```json
{
  "anchor_kind": "fact|intent|execution|branch",
  "anchor_id": "...",
  "mode": "resume|fork|fresh_context",
  "worker_name": "optional",
  "source_execution_id": "optional"
}
```

规则：

- `fork/resume` 必须有 source execution 且 `remote_session_out_status='available'`。
- worker identity 默认继承 source execution。
- fork availability 只读 worker inventory capability；server 不硬编码 Codex。
- Fork/Resume availability 还必须通过统一 availability service 检查 source execution 的 environment/endpoint/model profile 与当前 inventory、endpoint、runtime health 是否仍匹配。
- `fresh_context` 可无 source session。
- `POST /branches/{branch_id}/fork` 是从已有 branch 某个 cursor/execution 创建子 branch 的便利 API；内部仍落为一条 `branches(mode='fork', parent_branch_id=...)` 记录，不新增产品概念。

2. `POST /projects/{project_id}/branches/{branch_id}/messages`：

- Server 创建 pending `ExecutionRun(task_type='question', branch_id=...)`。
- 同 transaction 写 user `ExecutionEvent(event_type='message', role='user')`。
- 同 transaction 固定本轮 `remote_session_in_*` 与 `session_action`，避免 dispatcher lease 时重新猜 session。
- Dispatcher 后续只 lease 这个 pending execution。
- remote session 推导：
  - branch 无 successful execution：用 source execution `remote_session_out`。
  - branch 有 successful execution：用最近 execution `remote_session_out`。
  - fresh_context 无 remote session，可带 prompt context snapshot。
- `session_action`：
  - fork 第一轮：`fork_initial`。
  - fork 后续轮：`branch_continue`。
  - resume：`resume_continue`。
  - fresh：`fresh_context`。

3. Session lock：

- 对 `resume_continue` 在 message execution 创建事务内获取 `execution_session_locks`。
- key 为 `(project_id, remote_session_kind, remote_session_id)`。
- terminal/recovery/explicit cancel 释放。
- fork branch 后续 continuation 使用 branch 自己的 forked session，不锁 source session。

4. Dispatcher question task：

- lease pending question execution。
- 根据 `session_action` 调 driver：
  - `fork_initial` -> backend fork command。
  - `branch_continue` -> backend resume/continue command。
  - `resume_continue` -> backend resume source command。
  - `fresh_context` -> no remote session, include branch history summary.
- assistant/tool/stdout/stderr/session 全部写 execution events。
- terminal patch `remote_session_out`。

5. `GET /branches/{branch_id}/timeline?after_cursor=...`：

- 从 branch executions + execution_events 投影。
- 不缓存为事实源。
- 支持 project-level cursor。
- 跨 execution 按 `project_seq` 排序。
- `after_cursor` 必须支持刷新后幂等续读；foreign cursor 返回 400。

6. Promotion：

- Branch timeline promotion 可创建 hint/fact/intent。
- Server 在 promotion API 内事务写语义图；dispatcher 不调用 promotion/graph mutation API。
- Promotion metadata 记录 `branch_id`、`execution_id`、`event cursor`、`session_action`、remote session in/out。


### 验收

- 多轮 fork 不回到 source session。
- Resume 并发受控。

- timeline promotion metadata 含 `branch_id/execution_id/cursor/session_action`。

### 审查点

- 不允许存 `branch.current_session` 作为第二事实源。
- 不允许 server import driver 判断 fork。

## 风险与开放问题

1. Additive-to-destructive 两阶段会多一次过渡工作，但避免先删库导致系统不可运行。
2. SQLite event stream 高频写入可能放大。缓解：event sink batching、delta coalesce、大 event collapse。
3. Cursor 并发若设计不严会丢事件。缓解：transactional project counter + concurrency tests。
4. Resume 会污染 source session。缓解：server-owned `execution_session_locks`，expired recovery 对 resume 标 `failed_requires_manual_retry`。
5. Parser 放共享模块后需谨防 secret 泄露。缓解：parser 只处理 redacted stream payload，redaction 仍在 dispatcher sink 前执行。
6. Healthcheck 作为 execution 会增加噪声。Graph projection 默认隐藏，run detail 可展示。
7. Health read model 与 healthcheck execution 容易重复。边界：read model 决定可用性，execution 只提供审计和实时输出。
