Cairn v3 Planning

先把 worker run 变成可追溯事实，再让 UI 和 Q&A 站上去

v3 的关键不是“加一个聊天框”，而是修正事实链：Fact/Intent 必须能稳定追到 producing run，再从 DB provenance 找 remote session。没有这层，fork/resume 只是看起来像上下文相关。

核心架构

Source of Truth

DB RunProvenance

DB 记录 run_log_id、worker、workspace、report、remote session。JSONL 只做 raw/transcript artifact，不负责 session provenance。

Observation

Normalized Transcript

先全量重建 stdout/stderr，再解析 Codex/Pi/Claude 事件，最后按 normalized events 限制输出。Pi delta 必须合并。

Action

Temporary Q&A

fork/fresh_context 不入 DB，关闭即销毁 Cairn 侧 transcript。resume 是例外：确认后继续原 session，并写 run log。

实施路线

0 Contract先写 schema、parser、question contract 的失败测试与真实 fixture。
1-2 Provenance新增 migration；dispatcher 暴露 run_log_id；session 解析后更新 DB；fact 写 producing_run_log_id。
3-4 Transcript API完整 JSONL reader、worker parsers、runs/transcript API、anchor resolution。
5-6 Q&A Backendadapter capability、question runtime、resume lock、fresh context builder、promotion provenance。
7-8 UI & E2EConversation panel、Q&A composer、legacy/missing 状态、8000 端口真实 smoke。

边界矩阵

对象 保存什么 不保存什么 失败路径
Fact producing_intent_id、producing_run_log_id、report_run_id、report_path remote_session_id 旧 fact 只显示 legacy report id，session missing
RunProvenance run/session/workspace/report/finish/question provenance 完整 stdout 正文 session unresolved/missing 时禁用 fork/resume
Run JSONL outer stream、raw transcript、可选 session_resolved 镜像 唯一 session 索引 legacy JSONL 可 raw 查看，但不恢复 session
QuestionThread 短期 transcript、anchor、mode、source session status fork/fresh_context 的 DB 持久 transcript 关闭或 TTL 后 410；resume run 仍可追溯

UI 改动

Panel

Detail 变轻

Detail 只放对象元信息与主要动作。Worker Output 从 intent detail 内移走，进入独立 Conversation tab。

Conversation

结构化看 run

Conversation / Tools / Raw 三视图。message 分角色，tool call 默认折叠，大事件内部折叠，默认最后 200 条 normalized events。

Ask

历史对象可追问

已结束 exact anchor 才显示可用 fork/resume。missing anchor 只显示 fresh_context。running intent 暂不显示 Ask。

Warning

resume 必须确认

resume 会继续原 remote session，可能影响远程日志和上下文；UI 必须给确认与并发冲突反馈。

主要风险

双写不一致
DB provenance 写失败时不能假装 session 可用；UI 标 has_provenance=false。
Pi 大日志
100MB JSONL 不能逐 delta 渲染；parser coalesce 是硬门槛。
resume 污染
确认弹窗、session lock、timeline/run log 三件套缺一不可。
fork 过早承诺
不凭 backend 名字猜能力；未验证 CLI 前 fork capability 关闭。

验收口径

最小可上线切片应先交付 Provenance + Transcript Panel：新 run 可 exact 追溯，旧数据明确 missing，Codex/Pi/Claude transcript 可结构化展示。Q&A 在此基础上接入；没有 DB provenance 的“问当时 worker”一律不许伪装。
实现可开始的条件：v3 spec 已确认；versioned migration runner 已存在；当前 plan 已列出 schema、API、dispatcher、parser、UI、Q&A、E2E 的阶段与验收。实现前只需决定一个小点：Claude fork 是否等本地 CLI 验证后再开启，默认建议先不开。
