Execution Plan · v3.1 Q&A Correction

先钉边界，再写代码

新计划把 server、dispatcher、driver、environment、run provenance、question runtime 的职责写成硬契约。目标不是“能跑一次”，而是防止前期边界漂移，保证后续实现可维护、可测试、可恢复。

Server

控制面

保存 question runtime、resolve anchor、读 capability、promotion、transcript API。不 import driver，不连远端，不跑 worker。

Dispatcher

执行面

claim question job，选 worker/env，调用 driver，执行进程，回写 events/result/provenance。

Driver

backend adapter

声明真实 capability，构造 fork/resume/fresh_context 命令，解析 session，不写 DB。

Truth

RunProvenance

run/session 的事实源是 DB。run JSONL 是 raw transcript artifact，不负责 backfill session。

Runtime

QuestionRuntime

跨进程短期状态。close/TTL 后清理，不是长期 archive；resume 的 run provenance 另行保留。

禁止

server direct execution

server 不得运行 worker、不得读取 secret 以执行 worker。

driver import in server

server 不得 import get_driver 算 capability。

sync long request

POST /questions 不得等 worker 完成。

resume as fork

不得把污染原 session 的 resume 包装成 fork。

state without recovery

不得用“短期不保存”为由跳过 lease、requeue、cancel 与 restart recovery。

mock as delivery

不得用 Mock fork、Claude Code fork 或 unavailable reason 替代 Pi/Codex fork 交付。

必须

real fork

v3.1 必须做出 Pi fork 与 Codex fork；Claude Code fork 可后续补。

fresh history

fresh_context 多轮必须带历史或摘要。

resume lock

同一 source session 只能一个 active resume。

source truth

run/session 事实只信 DB provenance。

event idempotency

dispatcher 重试不得制造重复 event 或 terminal state。
