# V3.3 Frontend Refactor Execution Plan

依据：`docs/specs/v3.3-frontend-refactor-requirements.md`
日期：2026-05-20
状态：待确认执行计划

## 0. 目标边界

### 0.1 核心判断

V3.3 不应做成“把 `index.html` 拆成许多文件”。当前风险的根不是文件长度，而是前端同时承担 API client、projection 解释、selection 状态、execution stream、worker transcript parser、polling scheduler 与 UI renderer。

本计划选择直接迁移到 `React + TypeScript + Vite`，而不是继续 Alpine 模块化。

理由：

- `Graph / Detail / Output / Ask / Log / Replay / Environment` 的交互状态已超过 Alpine 单 store 的舒适区。继续 Alpine 可以减少短期改动，但很难把 selection reducer、execution stream cursor、question branch lifecycle 做成可靠单元测试。
- TypeScript 能把 `/ui-projection`、execution events、branch timeline、question availability 的 shape 显式化，降低“裸 dict 字段漂移”。
- React 组件边界更适合把 Cytoscape 封成 imperative island，同时让 Inspector、Output、Ask、Environment 等面板可测。
- Vite/Vitest/Playwright 能补齐 spec 要求的 pure function、component smoke、browser E2E 与 visual smoke。

反方最强论证是：引入 npm 工具链会增加仓库复杂度，并破坏当前 `cairn serve` 一体化体验。此风险成立，所以执行约束为：

- npm 只作为开发/构建依赖，不成为 `cairn serve` 运行时依赖。
- 生产静态产物仍由 FastAPI 内置托管。
- 迁移期间保留 legacy UI fallback，避免大重构中间态不可用。
- 先立 contract 与测试护栏，再替换 UI 主路径。

### 0.2 架构目标

目标架构：

```text
FastAPI projection contract
  -> ApiClient
  -> typed domain stores / reducers
  -> React panes
  -> Cytoscape GraphCanvas imperative island
```

边界要求：

- Server 负责语义投影：`ProjectUiProjection`、execution runtime projection、worker capability、question availability、timeline/replay 所需字段。
- Frontend 负责消费和渲染：不得在主路径按 Codex/Pi/Claude stdout JSON 推导产品语义。
- `GraphSelectionStore` 产出唯一 `conversationAnchor`。Graph、Detail、Output、Log、Ask 必须围绕同一 anchor。
- 每个 polling stream 有 owner、cursor、status、timer/cancel，切换项目或 selection 时必须取消旧 stream。
- Raw fallback 保留，但标记为 legacy/debug fallback，不得成为主 conversation 事实源。

### 0.3 非目标

- 不重定义 `Fact`、`Intent`、`ExecutionRun`、`ExecutionEvent`、`Branch`、`Artifact`。
- 不把 UI 改成 landing page。
- 不在 V3.3 新增核心后端能力；后端只补 UI projection 与 normalization contract。
- 不追求像素级一致；追求语义、入口、状态、工作流不退化。
- 不恢复旧 `/questions` 或 `/runs/*/transcript` 作为 Output/Conversation 主路径。

## Phase 0: Contract First 与测试基线

### 目的

先冻结后端 projection 与前端纯逻辑契约，防止重构期间“看起来能跑，锚点错了”。Phase 0 可以先产生 RED，但 RED 必须指向真实缺口。

### 步骤

1. 新增 `ProjectUiProjection` response model。

建议模型：

```text
ProjectUiProjection
ProjectFactProjection
ProjectIntentProjection
ProjectTimelineEntryProjection
ExecutionAnchorProjection
QuestionAvailabilityProjection
WorkerCapabilityProjection
ArtifactSummaryProjection
```

最低字段覆盖 spec 6.2：

```text
project
facts[].id/title/description/metadata/kind/status
facts[].producing_execution_id/produced_by_execution_id/artifact_summaries
intents[].id/from/to/description/creator/requested_worker/worker_name
intents[].runtime_status/active_execution_id/latest_execution_id
intents[].concluded_fact_id/blocked_reason
hints[]
timeline_summary or timeline_entries
worker_capabilities / ask availability read model
```

2. 新增主入口：

```http
GET /projects/{project_id}/ui-projection
```

`GET /projects/{project_id}/graph` 保留为兼容 alias，但实现必须调用同一个 service builder。新测试、新前端、新文档统一称 `ui-projection`。

3. 抽出 service：

```text
build_project_ui_projection(conn, project_id) -> ProjectUiProjection
```

该 service 负责：

- 从 `execution_runs` 派生 intent runtime projection。
- 从 fact provenance 派生 fact producing execution。
- 汇总 artifact summaries。
- 给 Ask 提供可用 mode 与 unavailable reason。
- 给 Timeline/Replay 提供稳定输入，不让前端重新拼语义日志。

4. 增加 API contract tests，必须用 FastAPI `TestClient`，不只 router 直调。

建议新增：

```text
cairn/tests/server/test_v33_ui_projection_contract.py
cairn/tests/server/test_v33_execution_events_contract.py
cairn/tests/server/test_v33_branch_availability_contract.py
cairn/tests/architecture/test_v33_frontend_legacy_api_guards.py
```

断言：

- `/projects/{id}/ui-projection` 返回 Pydantic response model，可序列化。
- `/projects/{id}/graph` 与 `/ui-projection` 在过渡期等价或为兼容子集。
- running intent 的 `active_execution_id`、`latest_execution_id`、`runtime_status` 来自 `execution_runs`。
- completed fact 能锚到 `producing_execution_id`。
- execution events cursor 支持 `after_cursor`、`limit`、非法 cursor、跨 project cursor。
- Ask availability 的 fork/resume/fresh_context 来自 server projection，不按 worker type 在 UI 硬编码。
- UI 主路径禁止 `/questions` 与 `/runs/*/transcript`。

5. 建立前端测试基线目录，但先不迁 UI。

新增 `cairn/frontend`：

```text
package.json
vite.config.ts
tsconfig.json
vitest.config.ts
playwright.config.ts
src/contracts/
src/domain/
src/stores/
src/components/
src/graph/
src/api/
tests/unit/
tests/e2e/
```

6. 把 legacy `index.html` 复制或移动为 `legacy-index.html`，并让 `/` 在迁移期可 fallback。

推荐策略：

```text
if static/app/index.html exists:
    serve static/app/index.html
else:
    serve static/legacy-index.html
```

等 Phase 6 后再删除 fallback。

### 测试

```bash
PYTHONPATH=cairn/src python -m pytest \
  cairn/tests/server/test_v33_ui_projection_contract.py \
  cairn/tests/server/test_v33_execution_events_contract.py \
  cairn/tests/server/test_v33_branch_availability_contract.py \
  cairn/tests/architecture/test_v33_frontend_legacy_api_guards.py -q
```

```bash

npm install
npm run test:unit
```

### 验收

- `/ui-projection` 成为正式 contract。
- `/graph` 不再是新代码命名基准。
- 前端测试环境能运行。
- legacy UI 仍可通过 `cairn serve` 打开。

### 审查点

- 若 React scaffold 已建但 contract 未稳，停止迁 UI。

## Phase 2: Typed API Client 与 Domain Reducers

### 目的

把旧 `cairnApp()` 中最危险的产品逻辑先迁成可测试纯模块，再接 UI。

### 步骤

1. `src/contracts/` 定义 TypeScript contract：

```text
projectUiProjection.ts
executionEvents.ts
branches.ts
workers.ts
environments.ts
```

原则：

- 类型名称与 server response model 对齐。
- 只在 API boundary 做 runtime validation 或 defensive normalization。
- 内部组件不直接消费裸 JSON。

2. `src/api/client.ts`：

- 统一 HTTP method、JSON/text 读取、错误规范化。
- 支持 `AbortSignal`。
- 所有 polling API 必须可取消。

3. `src/domain/graphModel.ts`：

- `buildGraphElements(projection)`。
- 不访问 DOM，不 fetch。
- 覆盖 origin/goal/fact、multi-source intent、open/running/unclaimed/concluding/conclude_failed/bootstrap。

4. `src/domain/selection.ts`：

```text
selectionReducer(state, action)
resolveConversationAnchor(projection, selection)
resolveGraphFocus(projection, selection)
resolveTimelineSelection(projection, selection)
```

唯一 anchor 模型：

```text
fact | intent | execution | branch | multi_fact | none
```

5. `src/domain/conversation.ts`：

- `executionEventToConversationEvents`
- `compactConversationEvents`
- `terminalStatusByExecution`
- Messages/Tools/Raw filter
- Legacy raw parser 只放 `legacyWorkerJsonFallback.ts`，调用点需显式标记 debug fallback。

6. `src/domain/questionAvailability.ts`：

- 只消费 server projection。
- 不写 `if worker_type === "codex"` 这类 UI hardcode。

7. `src/domain/polling.ts`：

- stream reducer：idle/loading/running/error/disposed。
- cursor、backoff、cancel owner。

### 验收

- 旧 `index.html` 中的产品逻辑已在 TS pure modules 中有等价测试。

- 若组件内重新写一套 selection 推导，停止。

## Phase 4: ExecutionStream、Output 与 Ask

### 目的

迁移最高风险区：running output、completed output、Raw fallback、Ask fork/resume/fresh_context。

### 步骤

1. `ExecutionStreamStore`：

- 根据 `conversationAnchor` resolve source execution。
- 调 `/executions/{id}/events?after_cursor=&limit=`。
- 保存 cursor。
- running execution 1s 轮询。
- idle backoff。
- anchor/project/panel close 时 abort。

2. `ConversationViewModel`：

- Messages、Tools、Raw 三视图。
- terminal status。
- missing provenance reason。
- events omitted / compaction。
- resume branch timeline 合并到主 Output。
- fork/fresh branch timeline 只显示在 Ask thread。

3. `QuestionBranchStore`：

- mode selection 来自 server availability。
- fork 默认优先。
- resume 需确认 modal。
- branch continue 复用 active temp branch。
- Fresh Context 无 session 时可用，但 UI 明示不是原 session。

4. `AskPane`：

- composer。
- mode buttons + unavailable reason。
- active thread timeline。
- loading/error/empty states。
- close temp branch 后不污染主 Output。

5. Negative guard：

- 新 React 代码禁止 `/questions`。
- Output 禁止 `/runs/*/transcript`。
- worker-specific parser 只能在 Raw debug fallback module 出现。

### 测试


E2E 覆盖：

- completed fact/intent 默认锚到 producing/latest execution。
- Messages/Tools/Raw 均可用。
- missing provenance 有 reason，Fresh Context 可用。
- Fork 可用时能发起两轮临时 branch。
- Resume 必须确认，确认后进入主 Output/branch timeline。
- Fork unavailable reason 可见且按钮不可点击。

### 验收

- Output/Ask 不再依赖 legacy transcript 主路径。
- Server availability 与 UI action 一致。
- 切换 selection 不串流、不重复轮询。

### 审查点

- 若 server projection 标记 Fork unavailable，UI 仍允许点击，停止。
- 若 running intent Output 空白且无 pending/no events 状态，停止。

## 风险与开放问题

1. npm 依赖进入仓库会增加维护成本。
   决策：接受为 dev/build 成本；禁止成为 `cairn serve` runtime 依赖。

2. Vite build artifact 是否提交。
   建议：应用型仓库提交 `cairn/src/cairn/server/static/app/` production artifact，保证 Python-only 运行与包内 UI 可用；同时把 artifact 视为生成产物，代码审查重点看 `cairn/frontend/src`。

3. Cytoscape layout 迁移可能造成视觉偏差。
   决策：不追求像素一致；用 visual smoke 保证非空、可读、不遮挡。

4. Server projection 可能继续膨胀。
   决策：`ProjectUiProjection` 是 UI read model，不是任意 dump。字段新增必须有 component consumer 与 contract test。

5. Legacy parser 保留可能反向污染主路径。
   决策：放独立 fallback module，并用 architecture test 禁止主 ViewModel import。

6. E2E 需要稳定 fixtures。
   决策：优先用 FastAPI test fixture + seeded DB + mocked execution events；真实 dispatcher/worker 仅做 manual E2E，不作为默认 CI 前置。

## 最终验收清单

- `GET /projects/{id}/ui-projection` 有稳定 response model 与 TestClient contract tests。
- `GET /projects/{id}/graph` 仅为 compatibility alias。
- React/TS/Vite 前端由 `cairn serve` 静态托管，用户无需单独启动前端服务。
- ProjectList、Graph、Detail、Output、Ask、Log、Settings、Hints、Environment、Replay 能力不退化。
- Graph/Detail/Output/Log/Ask 使用同一 `conversationAnchor`。
- Execution events 是 Output/Conversation 主事实源。
- Fork/Resume/Fresh Context availability 来自 server projection。
- 每个 polling stream 可取消，切换项目/selection/panel 不串流。
- Browser E2E 覆盖 spec 9.2 的关键流程。
- Visual smoke 覆盖桌面与窄屏，Cytoscape canvas 非空，长文本不遮挡。
- 新前端主路径不调用 `/questions` 或 `/runs/*/transcript`。
- README 写明 frontend dev/build/test 与最终 validation path。
