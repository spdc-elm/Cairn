先协议，后调度，最后 UI

计划不从界面开刀。先把 server schema/API 与测试钉牢，再补 workspace/report，最后接 dispatcher 与 WebUI。

Phase 0-2

Contract tests、DB migration、project/intent/fact API。

Phase 4-6

Workspace、report 硬约束、worker selection 与 timeout。

Phase 8-12

WebUI、日志、文档、Docker Kali 手动验收。

关键取舍：宁可先让 API 与 dispatcher 语义正确，再让 UI 跟上；避免表单先行导致协议含混。

新增字段显式化，不复用旧字段

Intent.worker 继续只表示 lease holder；人工指派进入 requested_worker。

对象新增核心字段原因
Projectauto_reason, allowed_auto_workers_json, default timeouts运行时策略归 server，不写 YAML。
Intentrequested_worker, timeout overrides, control_state订单与 lease 分离。
Factmetadata_json记录 report path，fact description 保简。
关键取舍：server 不校验 worker 是否真实存在；真实兵力来自 dispatcher inventory，避免 server 与部署配置强耦合。

Worker inventory 由 dispatcher 上报

当前 dispatcher 不是 HTTP server。最小可维护路径是 dispatcher 周期性把安全的 worker 视图 publish 到 server，UI 从 /workers 读取。

上报内容

name/type/model_profile/endpoint/task_types/max_running/priority/allowed_environments

禁止上报

worker.env、resolved endpoint secret、API key、token。

PUT /workers
[
  {"name":"pi-GPT5.5","type":"pi","task_types":["explore"],"max_running":2}
]

Report 成为硬防线

成功 fact 之前必须检查 report 存在且在 workspace 内；缺 report 就 fallback，fallback 也失败则写失败 report 并回 pending。

Environment 抽象扩展

exists/read/is_path_in_workspace/report_path 留在 backend 内部，task 层不分 Docker/SSH 拼路径。

Docker 补 workspace

/home/kali/workspace/.cairn/projects/{project_id}，并注入 CAIRN_WORKSPACE。

关键取舍：不靠模型 JSON 返回长报告；模型写文件，dispatcher 验文件，fact 只记 metadata。

验收聚焦四件事

测试覆盖不是补丁：每个关键语义都有单测/API 测试/dispatcher 测试，最后在既有 pentestVM Docker/Kali 环境中手动闭环。

验收点证明方式
默认人工决策API 测试 + UI smoke：新项目 auto_reason=false。
指定 worker 不 fallbackdispatcher selection test + docker exec -it pentestVM zsh 手测两个 intent 抢同一 worker。
conclude_now 正确收尾cancellation reason test + 手动点击 request conclude。
report/fact metadata 闭环report tests + 在 pentestVM 中检查 report 文件存在，且不触碰 /home/kali/ctf。
最大待定点：bootstrap 首版计划保留当前自动行为；若要“完全人工”，需单独加 auto_bootstrap，不要偷用 auto_reason。
