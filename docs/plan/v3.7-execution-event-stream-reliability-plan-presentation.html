v3.7 Execution Event Stream Reliability

目标是把 resume/fork、ExecutionEvent 写入、Output 实时预览和可观测性拉回同一个清晰契约：每轮执行一个 ExecutionRun，事件主链路稳定、实时、可诊断。

核心判断

不是 batch size 问题

too_long 251 是 409 后队列滚雪球的次生灾害，根因是同 execution 被重写或 close-side events 重复生成。

ExecutionRun 是原子边界

fork/resume 每一轮必须创建新的 execution，不能复用 source execution id 重新从 status:1 写事件。

event_key 是稳定幂等键

同 key 不同 event 仍必须冲突；修复方向是 single writer 和确定性 key，不是吞掉冲突。

single writer 需要 token

leased_by 只能区分 dispatcher，不能区分同 dispatcher 的 stale sink；append/finish/patch 需要持久 sink_token。

内部写入分流

branch 初始 user event 与 manual conclude terminal event 走 server-internal helper，不套 dispatcher append 权限。

诊断不泄漏 payload

server canonical diff 只打 hash/shape，不输出 raw stdout、message 或 API key preview。

实施路线

0. 基线测试固定 409、251、重复 raw metric、terminal append 等失败模式。
1. Server 契约状态/owner guard、terminal replay、finish barrier、conflict diagnostic。
2. EventSink 状态机拆分 live flush 与 finish，切片批量，409/422 fail-fast。
3. Branch 稳定性每条 branch message 新 execution，resume lock 释放，fork lineage 正确。
4. UI 实时预览running、last event age、bounded diagnostic、长输出持续可见。
5. 可观测性结构化日志、canonical diff、sink summary、诊断 SQL。
6. SSOT 合并实现后把 single-writer、state machine、UI 规则写回架构事实源。
7. E2E 验收真实 server/dispatcher/browser/worker 流程跑完 fork 和 resume。

验收重点

稳定性

  • terminal execution 后不能追加新事件。
  • fork/resume 多轮不复用 source execution。
  • owner + sink token 阻止第二个 stale sink。
  • 409/422 后不刷屏，不出现 251 events。

实时体验

  • 2 秒内看到 running。
  • 5 秒内看到 3 个 1s marker。
  • 运行中 last event age 小于 3 秒。
  • final assistant/status 不丢、不被 terminal 抢跑。

UI 隔离

  • fork 输出关闭和刷新后不进入 source。
  • resume 输出刷新后进入主 history。
  • 1000+ events 不爆 DOM，不铺开大 diagnostic。

可观测性

  • 日志能关联 execution、sink、batch、event key、run log。
  • 409 只打 hash/shape diff。
  • 诊断事件不进入普通 Conversation。

架构取舍

优先强化现有 ExecutionRun / ExecutionEvent 主链路，不引入旧 transcript 或 run provenance 兼容路径。本轮接受 schema delta：为 dispatcher writer 增加 sink_token 或等价 generation，专门解决同 dispatcher stale sink。

最大风险

如果只修 EventSink 而不修 server append guard 和 branch execution lifecycle，下一次仍可能由另一路复用 execution id 触发同类冲突。因此计划把 server contract 放在 EventSink 重构之前。
